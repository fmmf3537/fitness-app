# UI/UX Review · 健身看板 · 2026-09-15

> 评审范围：frontend/src 全部 page + component；当前状态基于 UIX-10 后的截图版本。
> 文档约定：所有「应该」都附原文出处，便于对照修改。

---

## 0. 总评

整体已形成统一的设计地基（indigo-600 主色、44px 触控热区、min-h 暗色对比统一、组件仅来自 `src/components/ui/`），这是非常扎实的基础。但作为「个人健身数据中台 + AI 教练」这个产品定位，目前的 UI 仍偏「后台管理」而非「教练陪伴」：

- **核心场景（看一眼今天该练什么 / 复盘上周 / 跟教练聊）的视觉权重与次要场景（配置 LLM Key / 已删除训练恢复）相当**——用户进入 app 后第一眼很难知道「下一步该做什么」。
- **数据展示多于洞察引导**：趋势页 4 张图、复盘页 1 份报告，但缺少「一句话告诉你意味着什么」——训练量同比 / 睡眠拖累容量 / 这周该调整哪些部位。
- **移动端核心导航（5 Tab）vs 桌面端核心导航（8 Tab）的不对称**，导致同一功能在两端体验不一致。
- **「我的」作为 Tab 名字错位**——它实际承担了设置 + 个人资料 + 已删除恢复 + 功能菜单 4 件事。

## 1. 信息架构与导航（IA / Nav）

### 1.1 「我的」Tab 名实不符
- 现状：`/settings` 路由名 + 页内塞了「LLM Provider / API Key / 用量 / 个人资料 / 已删除训练 / 功能菜单」6 件事。
- 桌面 header 第 8 项叫「我的」，但移动端 BottomTabs 第 5 项也叫「我的」。
- **问题**：「我的」语义上应该是用户档案，但在本 app 它是「设置 + 工具合集」。
- **建议**：保留 `/settings` 路由做设置面板，但 BottomTabs 第 5 项改为「我」（头像 + 用户名），点进去再分 Tab：资料 / 设置 / 教练须知；或者把已删除训练恢复挪到「设置 → 数据管理」二级页。

### 1.2 桌面 13 → 8 后的二级入口仍然割裂
- 现状（`Layout.jsx`）：桌面 header 有 `NAV_LINKS`（8 项），移动端 header 还有一个汉堡菜单 `SECONDARY_LINKS`（5 项：待确认队列 / 复盘 / AI 报告 / 身体数据 / 数据导入）。
- **问题**：用户切桌面/移动端，同一功能的入口路径不一致（如「AI 报告」桌面在 header，移动端藏在汉堡）。
- **建议**：把汉堡菜单也做成全局组件（任意端可见的「更多」入口），或者将「复盘 / AI 报告 / 身体数据」并入桌面二级 nav。

### 1.3 教练中心双 Tab 设计反模式
- 现状：`CoachHubPage` 是「聊天 / 教练须知」分段控件，底部 Tab `coach` 默认进入聊天。
- **问题**：教练须知是配置项（长期低频），跟聊天（高频）放在同一个页面入口，需要来回切；且教练须知其实更适合放在「我 → 设置」或独立路由。
- **建议**：`/coach` 只做聊天；教练须知改为 `/settings/coach` 或 `/me/preferences`。

### 1.4 待确认队列无强提醒
- 现状：`Layout.jsx` 在挂载时拉一次 `/api/match-candidates`，pending 数显示在 header 和底部 tab 图标旁。
- **问题**：拉取是 useEffect 一次性的，长时间使用 badge 不会更新；且仅在桌面 header 有橙色圆点，移动端 BottomTabs 完全没有 badge。
- **建议**：候选数做成全局 store（Context 或 Zustand），定时/同步完成后失效刷新；移动端 tab 上方加徽章。

## 2. 训练日历首页（CalendarPage）

### 2.1 header 三件套布局混乱（移动端）
- 现状：`flex flex-wrap` + `max-md:basis-full` 让 SyncButton 单独占第二行，移动端看起来「上面一行三个东西，下面又一个大按钮」，视觉重心失衡。
- 改进（见原型 `07-home-improved.html`）：
  - 月份切换紧凑化（`‹` `›` 单字符按钮，去掉文字）
  - 同步按钮与「更多」合并到右上角图标按钮组
  - 头部下方新增「本月统计条」（训练天数 / 总容量 / 待确认数）
- **新增**：日历格内增加可读性更强的小标签（不止 1 个圆点，可叠加 `+` 表示多训练）。

### 2.2 图例压在底部且无视觉权重
- 现状：图例「已匹配 / 仅单源 / 待确认」挤在日历下方一行小字。
- 改进：图例上移到月份标题旁或日历上方 4px 间距；或用 chip 形式带计数。

### 2.3 缺少年/月维度切换
- 现状：只能月视图。
- 建议：增加「月 / 周」切换 chip。周视图对每天都有训练的高频用户更实用（一眼看到 Mon/Wed/Fri 的训练密度）。

### 2.4 今日入口缺失
- 现状：用户想跳回今天得点月份切换器到含今天的月份——日历没「回到今天」快捷按钮。
- 改进：在月份标题旁加 `今` chip；用户不在当月时显示，点了回到今日。

## 3. 训练详情页（WorkoutDetailPage）

### 3.1 SummaryCard 数据维度挤
- 现状：`grid-cols-2 sm:grid-cols-4`，移动端 4 项变 2 项 2 行，丢失「一眼看完」的体验。
- 改进（见 `08-workout-detail-improved.html`）：
  - 顶部「关键指标横滑」一行：`⏱ 47 min · 🔥 412 kcal · ❤️ 142 bpm` 一行式紧凑布局
  - 或使用「Hero 数字 + 单位 + 上下文注解」的卡片化展示（参考 GitHub 风格）

### 3.2 删除按钮暴露且无分级
- 现状：`删除此训练` 在详情最底部，跟「分享海报」挨着，危险操作无视觉区分。
- 改进：删除按钮移入「更多 ⋯」菜单内，菜单里同时放「重新匹配佳明」「查看原始数据」「删除」。

### 3.3 Tab 切换无下划线过渡
- 现状：`border-b-2 border-indigo-600` 是直接切换，无 motion。
- 改进：加 `transition-all duration-150`；考虑用滑动下划线（active indicator）。

### 3.4 动作表在小屏可读性弱
- 现状：`MovementsTable` 是 `<table>` + `overflow-x-auto`，列多时小屏必须横滑。
- 改进：移动端折叠为每组一张卡（顶部一行元数据，下方组数列表），桌面保留表格。

## 4. AI 报告 / 复盘中心（AIReportsPage / ReviewsPage）

### 4.1 列表与详情 1:2 分栏在小屏退化为抽屉
- 现状：桌面三栏（列表 / 详情 / 空），移动端列表 + BottomSheet 弹详情。
- **问题**：抽屉弹出后用户失去列表上下文（不知道自己在第几条），且上一篇/下一篇按钮在抽屉 footer 容易误触。
- 改进（见 `12-profile-improved.html` 邻居的设计语言）：
  - 列表项改成横向 swipeable（参考 iOS Mail）
  - 详情用全屏页 push，header 提供「← 返回列表」
  - 上一篇/下一篇放在 header 右侧 chevron 组

### 4.2 报告生成状态弱反馈
- 现状：`{generating ? '生成中…' : '立即生成'}` + setInterval 轮询 status。
- 改进：进度条可视化（模型思考 → 写摘要 → 输出三段式进度）；失败时提供「重新生成」按钮 + 失败原因 tooltip。

### 4.3 缺少数数据洞察摘要
- 现状：周复盘详情是一大段 markdown。
- 改进：详情顶部加「Hero 数据卡」——本周训练 N 次 / 总容量 X 吨 / 与上周对比 ±X% / 平均 RPE X；这些数据 AI 点评会自动算出但用户看不到 summary。

### 4.4 评分卡头信息密度低
- 现状：`ScoreBadge` + 周期范围 + 重新生成按钮。
- 改进：评分卡做大数字 + verdict 文字（参考 `docs/prototypes/06-report.html` 已有的设计可保留并扩展）。

## 5. 趋势页（TrendsPage）

### 5.1 4 图等权，无主次
- 现状：`grid md:grid-cols-2` 4 张图均匀分布。
- 改进（见 `09-trends-improved.html`）：
  - 「每周总容量」升为主图（跨两列，高度 320px）
  - 其余 3 张辅助图紧凑（高 220px）
  - 每张图加「一句话洞察」副标题：「本周容量 X 吨（同比上周 +12%）」

### 5.2 4/12 周切换位置弱
- 现状：`PillGroup` 在标题右侧，与按钮同行容易跟其他控件混。
- 改进：移到页面顶部 tab bar 下方独立一行；右侧加「对比上周 / 上月」切换。

### 5.3 缺少关键指标 hero 卡
- 现状：用户进入趋势页只能看 4 张图，没有「本周关键 3 个数字」。
- 改进：顶部加 3 张 hero 卡：
  - 本周训练次数 N（同比 ±X%）
  - 连续训练天数 X 天
  - 本月最大 PR：深蹲 102.5 kg × 5

### 5.4 睡眠-容量散点图专业门槛高
- 现状：图绘制出来但用户不一定理解横纵轴含义。
- 改进：图下方加解读文字：「睡眠 < 6h 的训练容量平均下降 18%」——把 AI 已经算过的相关性显式呈现。

## 6. 待确认队列（CandidatesPage）

### 6.1 移动端「⇄」符号旋转 90° 不直观
- 现状：`sm:rotate-0 rotate-90`，在移动端 ⇄ 旋转成上下指向，看起来像箭头而非合并符号。
- 改进：用更明显的「并排重叠」图形（两个半透明圆叠加）；或干脆用纯文字「可能匹配」标签。

### 6.2 缺合并预览
- 现状：用户只能选择「合并 / 保持分开」，看不到合并后是什么样子。
- 改进：点「合并」先弹 diff 预览（合并后动作列表、心率曲线预览），确认再入库。

### 6.3 无筛选/排序
- 现状：列表是 API 返回顺序。
- 改进：顶部加筛选 chip（按日期 / 按 reason 类型）。

## 7. 教练聊天（CoachChatPage）

### 7.1 首屏空状态指引弱
- 现状：只给一个示例问题「我深蹲时膝盖疼……」。
- 改进（见 `10-coach-chat-improved.html`）：
  - 顶部加「教练能参考的数据」小卡片（最近 7 天训练 / 睡眠 / RPE / 体重）
  - 下方提供 4 个「快捷提问」chip：复盘上次训练 / 解读最近睡眠 / 下次训练重点 / 体脂变化趋势

### 7.2 「教练思考中」太弱
- 现状：单条静态文字「教练思考中…」。
- 改进：三点跳动动画（参考 iMessage）；或分段显示「正在读取本周训练 → 正在分析睡眠 → 正在生成建议」。

### 7.3 失败消息未持久化
- 现状：`failed` state 只保留最近一条，刷新页面丢失。
- 改进：失败消息标记后保留在列表（红色横条 + 重试按钮），用户即使离开再回来也能重试。

### 7.4 输入框无快捷操作
- 现状：纯文本框 + 发送按钮。
- 改进：输入框左侧加「+」按钮，弹出「引用训练 / 引用报告 / 拍照」快捷操作（参考 iMessage 附件）。

### 11.1 「立即同步」语义不清
- 现状：点了实际同步的是今天。
- 改进：改名为「同步今日」；旁边加 ⋯ 菜单提供「补录某天 / 触发历史融合」。

### 11.2 同步进度弱反馈
- 现状：Toast 提示 + inline 「同步中（约 1-2 分钟）」文字。
- 改进：进度条按阶段显示：连接佳明 → 拉取活动 → 拉取训练 → 匹配融合 → 生成点评。

## 12. 视觉/设计系统

### 12.1 阴影全是 `shadow-sm`
- 现状：Card 统一 shadow-sm。
- 建议：分级——浮动卡 `shadow-md` / 弹窗 `shadow-xl` / 普通卡 `shadow-sm`。

### 12.2 缺少图表主题规约
- 现状：ECharts 各图自定色。
- 建议：在 `utils/echartsMobile.js` 中统一品牌色板（indigo-600 / emerald-600 / amber-600 / rose-600），所有图表复用。

### 12.3 微动效缺失
- 现状：tab 切换、抽屉弹出都是瞬间。
- 建议：路由切换 150ms 淡入；抽屉 200ms ease-out；toast 250ms slide-up。

### 12.4 暗色模式对比度
- 现状：多处用 `dark:text-gray-400` 作为辅助文字（4.5:1 边缘）。
- 建议：辅助文字统一 `dark:text-gray-300`（7:1 通过 AA）；只有 disabled / 占位符才用 gray-500/400。

## 13. 可访问性（a11y）

- 全站缺统一 `focus-visible:ring-2 focus-visible:ring-indigo-500 focus-visible:ring-offset-2`。
- Tab 控件无 roving tabindex（箭头键导航）。
- ConfirmDialog 未实现 focus trap。
- 抽屉关闭后焦点未归还触发元素。
- ARIA：`role="status"`/`role="alert"` 已用，`aria-live="polite"` 应补在 toast 容器。

## 14. 移动端体验

### 14.1 缺下拉刷新
- 日历页 / AI 报告页 / 趋势页：用户只能点「同步」按钮触发刷新，缺少 swipe-to-refresh。

### 14.2 手势支持
- 报告列表无 swipe 切换上一篇/下一篇。
- 候选队列无 swipe 合并/分开。

### 14.3 Toast 与 BottomSheet 遮挡
- 当前 Toast 固定位置未与 BottomSheet 协同，可能被遮。

## 15. 反馈与引导

- **首次使用无 Onboarding**：登录后用户不知道「先设置 Key → 触发同步 → 等 AI 点评」。
- **空状态 CTA 弱**：除了「刷新计划」之外，其他空状态（身体数据 / 趋势 / 报告）都只给描述没给「立即创建」按钮。
- **失败无帮助入口**：LLM 调用失败 / 佳明 429 / 同步超时都只显示错误文本，没有「如何修复」链接或 FAQ 锚点。
- **进度可视化**：长任务（同步 / 历史导入 / AI 生成）只有骨架屏，没有分阶段进度条。

---

## 16. 数据展示密度

- 趋势页 4 图在移动端需要横滑；建议加横向 snap。
- 计划页 30 天垂直堆叠无分组（按周折叠）。
- AI 报告 / 复盘列表无分页或无限滚动——长列表性能风险（`/api/ai-reports` 当前是 limit 50？需要后端确认）。
- 身体数据「最近 30 条」硬编码截断——超过 30 天的历史看不到，需要加「查看全部」入口。

## 17. 改进优先级建议（3 个 Sprint）

### Sprint 1（基础体验，~1 周）
1. 日历页：紧凑 header / 图例上移 / 回到今天快捷（见 `07-home-improved.html`）
2. 「我的」页 iOS 风格化重排（见 `12-profile-improved.html`）
3. 训练详情页：Hero 数据行 + 删除移入 ⋯ 菜单
4. Toast 与 BottomSheet 协同（z-index / bottom 安全区）
5. 统一 focus-visible 焦点环

### Sprint 2（数据洞察，~1 周）
1. 趋势页：主辅图分级 + 关键指标 hero 卡（见 `09-trends-improved.html`）
2. 复盘页：Hero 摘要 + 全屏 push 详情
3. 教练聊天：快捷提问 + 思考动画（见 `10-coach-chat-improved.html`）
4. 身体数据：Hero 体重 + 录入表单 Tab 化（见 `11-body-metrics-improved.html`）

### Sprint 3（教练感与可访问性，~1 周）
1. 候选队列：合并预览 + swipe 操作
2. Onboarding 3 步引导
3. 下拉刷新 + 手势切换
4. 图表品牌色规约
5. 微动效统一
6. ConfirmDialog focus trap + 抽屉焦点归还

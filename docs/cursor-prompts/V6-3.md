## 开发内容

### 1. `services/exercise_mapping_llm.py`

模块 docstring 说明：用 LLM 为「无自动候选」的动作补候选；只写 candidate 表，
绝不改 mapping 主表、绝不自动激活。

#### 必需 API

```python
LLM_BATCH_SIZE = 20          # 每次请求多少个动作
LLM_MAX_BATCHES = 30         # 单次运行最多几批（防失控）
LLM_MAX_EXERCISES_PER_CATEGORY = 25   # 每个 category 送多少候选示例

def build_prompt(movements: list[str]) -> list[dict]:
    """构造 OpenAI 风格 messages。纯函数，可单测。

    对每个动作给出：部位（stats.classify_part）、该部位可用的 Garmin category 列表、
    以及这些 category 下最多 LLM_MAX_EXERCISES_PER_CATEGORY 个代表条目
    （格式 "CATEGORY / EXERCISE_NAME / Display Name"）。
    「其他」部位（categories 为空）时给全部 47 个 category 名但不给条目示例
    （避免 prompt 过长）。

    要求模型只输出 JSON 数组，元素形如：
      {"xunji_name": "...", "category": "...", "exercise_name": "...", "reason": "..."}
    并明确要求：category 必须来自给定列表；exercise_name 必须是该 category 下
    真实条目（可为空串）；不确定时把 exercise_name 设为空串并在 reason 说明。
    """

def parse_response(content: str) -> list[dict]:
    """从模型输出里抠出 JSON 数组并校验。纯函数，可单测。

    容错要求：
    - 剥离 ```json ... ``` 代码块围栏
    - 允许前后有解释文字（截取第一个 '[' 到最后一个 ']'）
    - 解析失败返回 []
    - 逐条校验字段齐全（xunji_name/category 必填），不合法条目跳过
    """

def validate_candidate(
    category: str | None, exercise_name: str | None, *, catalog: list[dict] | None = None
) -> bool:
    """校验 (category, exercise_name) 是否真实存在于 Garmin 目录。
    - category 必须在 exercises.CATEGORIES
    - exercise_name 为空串时只要 category 合法即通过
    - 非空时要求 ((category, exercise)) 在目录中（大小写严格）
    """

def suggest_candidates_with_llm(
    session: Session,
    *,
    limit: int = 200,
    max_batches: int = LLM_MAX_BATCHES,
    chat_fn: Callable[[list[dict]], dict] | None = None,
    only_without_candidate: bool = True,
) -> dict:
    """主入口。返回统计字典：
        {"requested", "processed", "batches", "accepted", "rejected",
         "skipped_no_candidate_list", "prompt_tokens", "completion_tokens"}
    """
```

#### 行为规格（**严格按此实现**）

**A. 挑选目标动作**

- 从 `app/data/xunji_movements.json` 读全部名字
- `only_without_candidate=True`（默认）时，只挑 `exercise_mapping` 里
  **`garmin_category IS NULL` 且 `status != 'not_applicable'`** 的行
  （这些正是 4 级窄化没命中的动作）；若无对应 mapping 行则也纳入
  （视为无候选）
- 按名字排序后取前 `limit` 个
- `limit <= 0` → 直接返回全 0 统计（不调 LLM）

**B. 分批调用**

- 每批 `LLM_BATCH_SIZE` 个动作，最多 `max_batches` 批
- `chat_fn is None` 时：
  ```python
  chat_fn = lambda msgs: llm.chat(msgs, session=session, purpose="exercise_mapping")
  ```
- 每批：`result = chat_fn(build_prompt(batch))` → `content = strip_think(result.get("content",""))`
  → `parse_response(content)`
- 累加 `result.get("prompt_tokens") or 0` / `completion_tokens`

**C. 校验与落库**

- 对每条解析结果：
  - `xunji_name` 必须在本批名单里（防模型臆造）
  - `validate_candidate(...)` 必须通过
  - 否则计入 `rejected` 并跳过
- 通过的：
  - 写 `ExerciseMappingCandidate`，`confidence='low'`、`rank=1`、`status='pending'`、
    `reason=f"LLM: {reason}"`（reason 为空时用 `"LLM 兜底候选"`）
  - **先删该 xunji_name 下 `status='pending'` 的旧候选**（与 batch 模块一致的幂等语义，
    `accepted`/`rejected` 永不删除）
  - **同时**把 `exercise_mapping` 该行的 `garmin_category` /
    `garmin_exercise_name` / `garmin_display_name` / `confidence='low'` 填上
    （`status` 保持 `draft` 不变——**绝不自动激活**）
  - 若该动作没有 mapping 行，则**跳过**（不新建行，避免与 batch 的 source 语义冲突），
    计入 `rejected`
  - 计 `accepted`

**D. 异常处理**

- 任一批 `chat_fn` 抛异常：记录后**继续下一批**（不整体失败），
  但连续 2 批异常则提前终止（防持续报错刷屏）
- 解析结果为空：计入 `rejected`，继续下一批

**E. 事务**

- 全部批次结束后一次性 `session.commit()`
- 中途异常不回滚已累计的结果（已写入的行在 commit 时一并落库）

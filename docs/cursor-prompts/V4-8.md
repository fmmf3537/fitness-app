## 需求（PRD-V4 F4 前端，开放问题已确认）

训练详情页「融合」标签的动作组次表，为每组追加**心率列**（组中均值/峰值 + 组后 30 秒恢复）：
- 低置信度组（佳明动作识别与训记动作不一致）数值前加 `~` 前缀；
- 该 workout 无逐组心率数据时（佳明无 exercise_sets / 老活动 / 未佩戴心率设备）**整列不显示**，
  表格保持现状逐字节不变。

## 已核实的关键事实（实读代码，可直接采信）

### 后端接口（V4-7 已交付，commit 6037b1b）

`GET /api/workouts/{id}` 响应新增 `set_hr` 键（后端保证始终返回，异常降级为 `[]`）：

```json
"set_hr": [
  {"movement_name": "深蹲", "set_index": 1, "hr_avg": 102, "hr_max": 104,
   "hr_min": 100, "hr_recovery_30s": 88, "confidence": "high"}
]
```

- `set_index`：**动作内原始 1-based 组序**——后端对齐时跳过 `done:false` 的组但保留其位置
  （已实读 `backend/app/services/set_hr.py:180-185` 确认 `enumerate(sets, start=1)`），
  因此前端直接用**组数组下标 i+1** 匹配，无需自己跳过未完成组。
- `confidence`：`"high"` / `"low"`；`hr_recovery_30s` 可能为 `null`（组后无心率采样）。
- `hr_avg`/`hr_max` 理论上也可能为 `null`（组窗口无心率点）。
- **注意**：后端按 (movement_name, set_index) 匹配，同名动作会共享数据——前端镜像此行为即可，
  不额外处理。

## 开发内容

### 1. `WorkoutDetailPage.jsx`

**`MovementsTable`** 增加可选 prop `setHr`（数组 / undefined / null）：

- 组件内构建查找表与显示开关：
  ```js
  const hrMap = new Map((setHr || []).map((r) => [`${r.movement_name}|${r.set_index}`, r]))
  const showHr = Array.isArray(setHr) && setHr.length > 0
  ```
- `showHr` 为 true 时，每个动作表 `<thead>` 的「完成」`<th>` 之后追加
  `<th className="py-1">心率 均/峰/恢复</th>`；为 false 时**表头与现状完全一致**。
- 组行对应追加 `<td className="py-1" data-testid="set-hr-cell">`，内容规则
  （取 `row = hrMap.get(`${mv.name}|${i + 1}`)`）：
  - 无匹配行 → 文本 `-`；
  - 有行：三槽位 `{hr_avg}/{hr_max}/{hr_recovery_30s}`——任一值为 null/undefined 该槽位
    显示 `-`（如 `102/104/-`、`-/104/88`）；
  - `row.confidence === 'low'` → 整体前加 `~`（如 `~101/104/88`）；
  - 给该 `<td>` 加 `title` 提示：高置信 `组中心率 均值/峰值/组后30s恢复（bpm）`，
    低置信 `低置信度：佳明动作识别与训记动作不一致，心率仅供参考`（测试不断言 title）。
- 页面第 163 行改为 `<MovementsTable movements={workout.movements} setHr={workout.set_hr} />`。
- 不改任何既有列、样式类名、key 逻辑；心率图、SessionReviewSection 等其他区块一律不动。

## 开发内容

### 1. prompt 注入「用户反馈」段（ai.py）

- `build_session_review_prompt` 与 `build_next_advice_prompt` 各加 keyword-only 参数
  `feedback: list[str] | None = None`（放参数表最后，不破坏现有调用）。
- feedback 非空时，user 消息在**历史段之后、恢复数据段之前**插入：
  ```
  # 用户反馈（来自本次训练后的讨论，请结合进点评/建议）
  - 用户：……
  - 教练：……
  ```
  （行内容即 feedback 列表各项，调用方已按「用户：/教练：」前缀格式化。）
- feedback 非空时，system 末尾追加一句：
  「附加要求：用户反馈为训练者本人补充的第一手事实（如身体状态、临场情况），
  你的输出须与之相符，不得与之矛盾。」
- feedback 为空/None 时两个 prompt 输出与现状**逐字节一致**（回归红线）。

### 2. 服务层重生成（ai.py）

新增常量 `REGEN_FEEDBACK_WINDOW = 10`、`REGEN_DAILY_LIMIT = 5` 与异常
`RegenerateLimitError(ValueError)`。新增两个函数：

```python
def _collect_feedback(session: Session, report: AIReport | None) -> list[str]:
    """report 为 None 返回 []；否则取其 report_chat_message 最近 REGEN_FEEDBACK_WINDOW 条
    （按 id 正序取尾部），格式化为 '用户：…' / '教练：…' 行。"""

def _check_regen_limit(session: Session, workout_id: int, report_type: str) -> None:
    """当日（按服务器本地日期）该 workout 该 type 的 ai_report 行数 >= REGEN_DAILY_LIMIT
    时抛 RegenerateLimitError（消息含'每日重生成上限 5 次'）。"""

def regenerate_session_review_with_feedback(
    session: Session, workout_id: int, *, chat_fn=None
) -> AIReport:
    """单 workout 删旧重生成 + 对话反馈注入。
    1. workout 不存在/已软删 → ValueError；
    2. _check_regen_limit(type='session_review')；
    3. 找该 workout 最新 session_review（created_at/id 倒序第一条），_collect_feedback；
    4. 删除该 workout 全部 session_review（仅该 type 且 workout_id 匹配）；
    5. 调 generate_session_review(session, workout_id, chat_fn=chat_fn, feedback=feedback)
       落新报告并返回。"""

def regenerate_next_advice_with_feedback(
    session: Session, workout_id: int, *, chat_fn=None
) -> AIReport | None:
    """同上，type='next_advice'；generate_next_advice 无计划缓存返回 None 时
    本函数也返回 None（旧报告已删——此场景前置校验：先确认 generate 能产出再删旧，
    即先收集 feedback→先跑 generate_next_advice 成功后再删旧重生成会导致重复调 LLM，
    因此约定：先删旧再生成，若无计划缓存返回 None，由 API 层转 422 提示；
    测试覆盖该分支）。"""
```

`generate_session_review` / `generate_next_advice` 各加 keyword-only `feedback=None`
透传给 builder。

### 3. API 端点（api/ai_reports.py，同步执行，与 report_chat POST 同先例）

- `POST /api/ai-reports/session_review/{workout_id}/regenerate_with_feedback`
  → 成功 200 `{"report": _serialize_report(...)}`；
  `RegenerateLimitError` → **429**（detail 透传）；workout 不存在 → 404。
- `POST /api/ai-reports/next_advice/{workout_id}/regenerate_with_feedback`
  → 同上；服务层返回 None（无计划缓存）→ 422 `detail="无训记计划缓存，无法生成下次建议"`；
  该 workout 当前无 next_advice 报告 → 404 `detail="该训练暂无下次建议"`。
- 两端点挂既有 router（自动继承 require_auth）。

## 测试要求（新文件 test_regenerate_with_feedback.py，用 conftest 的 session fixture + TestClient 范式参照 test_api_ai_reports.py）

1. **prompt 注入**：两个 builder 传 feedback=['用户：那天我感冒', '教练：注意休息'] →
   user 含 `# 用户反馈` 段与两行内容，system 含「须与之相符」；不传 feedback →
   与现状逐字节一致（可用既有 _workout_dict() 夹具，test_ai.py 可 import 的从 test_ai import）。
2. **session_review 重生成**：造 workout + 旧 session_review + 3 条 chat 消息，
   chat_fn 捕获 prompt 断言含「用户反馈」段且消息按序；旧报告被删、新报告落库、
   新报告 workout_id/type 正确；llm.chat 只调 1 次。
3. **无对话重生成**：旧报告无 chat → feedback 为空，prompt 不含「用户反馈」段，仍成功。
4. **日限 5 次**：造 5 条当日 created_at 的 session_review → 第 6 次抛 RegenerateLimitError；
   API 层返回 429 且 detail 含「每日重生成上限 5 次」。
5. **next_advice**：有对话的 next_advice 重生成注入反馈成功；workout 无 next_advice → API 404；
   无计划缓存（mock chat_fn 路径下 generate_next_advice 返回 None）→ API 422。
6. **API 鉴权/边界**：未登录 401（参照既有测试处理方式）；不存在 workout_id → 404。

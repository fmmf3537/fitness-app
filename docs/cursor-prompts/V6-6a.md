## 已核实的关键事实（实读代码，可直接采信）

### `map_plan_day` / `expand_workout` 已支持注入（V6-1 完成）

```python
def map_plan_day(plan_day, *, plan_ref=None, mappings=None) -> dict
def expand_workout(payload, *, mappings=None) -> list[dict]
```

`mappings` 为 None 时回退 `EXERCISE_WHITELIST`。注入的条目形如
`{"category","exerciseName","display_name","support_level","weight_strategy","status"}`。

**mapper 的 status 判定**：查不到 → `UNKNOWN_EXERCISE`；
查到但 `status not in (None, "active")` → `MAPPING_NOT_APPROVED`；
`status` 为 None 或 `"active"` → 正常映射。

## 开发内容

### 1. `exercise_mapping.py` 追加 `load_all_mappings`

```python
def load_all_mappings(session: Session) -> dict[str, dict[str, Any]]:
    """返回**全部**映射（含 draft/disabled/not_applicable），形状同 load_active_mappings。

    与 load_active_mappings 的区别：不过滤 status，让 mapper 的 status 判定生效——
    draft 的行会产出 MAPPING_NOT_APPROVED（而不是 UNKNOWN_EXERCISE），
    前端据此显示「此动作映射尚未复核」的引导。
    not_applicable 的行 **不返回**（这些动作本就不该进力量训练 payload，
    返回只会变成 MAPPING_NOT_APPROVED 噪音）。
    空表时回退 EXERCISE_WHITELIST 等价字典（同 load_active_mappings）。
    """
```

### 2. `garmin_plan_sync.py` 接入（4 处）

**a. `claim_plan_sync`（约 L358 的 `map_plan_day`）**

- 在函数内取一次映射：`mappings = load_mapping_service.load_all_mappings(session)`
- `preview = map_plan_day(plan_day, mappings=mappings)`
- 在**成功创建或复用 `GarminPlanSync` 记录时**写入快照哈希：
  ```python
  movement_names = [str(m.get("name") or "").strip() for m in (plan_day.get("movements") or [])]
  record.mapping_hash = load_mapping_service.load_mapping_snapshot_hash(session, movement_names)
  ```
  注意：`load_mapping_snapshot_hash` 内部按 active 映射计算；若某动作当前是 draft，
  它按 `(name, None, None, None, 0)` 参与哈希——这是 V6-1 既定语义，不要改。
- **不要**在 `plan_day` 缺少 movements 时抛错（既有逻辑已处理空动作）

**b. `_verify_workout_semantics`（约 L448 与 L587）**

- 函数签名加 keyword-only 参数：`*, mappings: dict | None = None`
- 两处 `expand_workout(remote)` / `expand_workout(desired)` 都传 `mappings=mappings`
- **必须两处都改**——它们是同一函数里两个不同分支（一处正向比对、一处语义比对）

**c. `run_plan_sync`（约 L600 的 `_verify_workout_semantics` 调用）**

- 该函数已有 session，取一次 `mappings = load_mapping_service.load_all_mappings(session)`
- 调用 `_verify_workout_semantics(record, remote, desired, mappings=mappings)`
- 若 `run_plan_sync` 内有多处调用 `_verify_workout_semantics`，**全部**传 mappings

**d. import 注意**

`garmin_plan_sync.py` 已有 `from app.services import ...` 之类的导入？**先读文件确认**
现有导入风格，再决定是 `from app.services import exercise_mapping as mapping_service`
还是 `from app.services.exercise_mapping import load_all_mappings, load_mapping_snapshot_hash`。
**避免循环导入**：`exercise_mapping.py` 不应 import `garmin_plan_sync.py`（当前也没有）。

### 4. `api/plans.py` 接入（1 处）

- `preview_garmin_plan`（约 L189）：取 `mappings = ...load_all_mappings(session)`，
  `map_plan_day(plan_day, mappings=mappings)`
- **额外要求**：该端点已把 `WorkoutMappingError.issues` 转成 422
  `detail={"code": "PLAN_MAPPING_UNSUPPORTED", "issues": [...]}`。
  现在 issues 里可能出现 `MAPPING_NOT_APPROVED`，**不要**新增分支——
  保持现有 422 结构不变（前端按 `issues[].code` 区分）。仅确认 issues 原样透传。
- **另需**：预览成功（200）时，响应里追加一个字段
  ```python
  "pending_review": [ {"xunji_name": ..., "suggested_category": ..., "suggested_exercise": ...} ]
  ```
  内容是「本训练日里 status='draft' 且有候选的动作」（用于 V6-6b 的引导弹窗）。
  实现：取本日 movements 的名字，查 `exercise_mapping` 里 `status='draft'` 的行，
  并从 `exercise_mapping_candidate` 取 rank-1 候选填充 suggested_*。
  若查询无 draft 动作 → 返回空 list（**不要省略该键**）。

## 5. 测试 `tests/test_garmin_mapping_wiring.py`（新，≥12 例）

里的（例如「海豹杠铃划船」→ `ROW/BARBELL_ROW`、「哑铃上凳」→ `SQUAT/DUMBBELL_STEP_UP`）。

4. `test_map_plan_day_uses_db_mapping` —— 用「海豹杠铃划船」+ DB active 映射，
   `map_plan_day(..., mappings=load_all_mappings(session))` 成功，且 category 来自 DB
5. `test_map_plan_day_rejects_draft_mapping` —— 同上但把该行改成 draft，
   断言 issues 含 `MAPPING_NOT_APPROVED` 且**不含** `UNKNOWN_EXERCISE`
6. `test_preview_endpoint_uses_db_mapping` —— 用 `client` + `auth_headers` 调
   `GET /api/plans/{day}/garmin/preview`，训练日含「海豹杠铃划船」，
   断言 200 且 `preview` 里该动作 category 来自 DB（非白名单）
7. `test_preview_endpoint_returns_pending_review` —— 该动作是 draft 且有候选时，
   响应含 `pending_review` 且含该动作、`suggested_category` 非空
8. `test_preview_endpoint_pending_review_empty_when_all_active` —— 全 active 时
   `pending_review == []`（键必须存在）
9. `test_claim_plan_sync_writes_mapping_hash` —— 走 `claim_plan_sync` 后

10. `test_mapping_hash_changes_after_mapping_edit` —— 改该动作映射并 bump version，
    重新 claim 得到不同 hash
11. `test_expand_workout_roundtrip_with_db_mapping` —— 用 DB 映射 map 出的 payload
    能被 `expand_workout(..., mappings=...)` 反向展开回原动作名
12. `test_reschedule_preview_uses_db_mapping` —— `preview_reschedule` 对 DB 映射动作成功

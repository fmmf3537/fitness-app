## 需求背景（方案见 `docs/EXERCISE-MAPPING-PLAN.md` §9）

V6-7 已把 1091 个动作落库，但 `verified_level` 只有 `none`（1075）与 `displayed`（16）。
`catalog` 级校验只能证明动作在 Garmin 目录里存在，**不能证明真实创建后 Garmin 会原样接受**。

已知真实坑（P2/P3 实测记录在 `docs/GARMIN-PLAN-SYNC-MIGRATION.md` §8.1）：
> Garmin 创建后会把通用 `Bench Press` 与 `Lateral Raise` 的 `exerciseName`
> **规范化为空串**，`category` 保持不变。

本切片做 **L2 探针**：对指定 `(category, exercise)` 组合，真实创建一个最小力量训练，
回读确认 Garmin 实际存了什么，**然后删掉它**（自清理），并把观测结果写回映射表。

**这是本方案里唯一会写 Garmin 的切片**，因此安全约束最多。

## 开发内容

### 1. 适配器新增 `delete_workout`

```python
def delete_workout(self, workout_id: str) -> None:
    """删除一个 Workout。**不可重试**（DELETE 的重复执行语义与结果不确定性）。"""
    self._call(
        "delete_workout",
        lambda: self._client.delete_workout(workout_id),
        retryable=False,
    )
```

放在 `update_workout` 之后，风格与既有方法一致。

### 2. `services/exercise_catalog_probe.py`

模块 docstring 必须写明：

> **本模块会真实创建并删除 Garmin Workout**。仅在
> `GARMIN_PLAN_SYNC_ENABLED=1` 且调用方显式给出 pairs 时运行；
> 每次创建的对象都会在回读后被删除（除非 `keep=True`）；**不创建任何日程**。

#### 必需 API

```python
PROBE_MAX_ITEMS = 30          # 单次最多探测多少个组合

@dataclass(frozen=True)
class ProbeResult:
    category: str
    exercise_name: str
    status: str               # "verified" / "normalized" / "failed"
    observed_category: str | None
    observed_exercise_name: str | None
    observed_display_name: str | None
    workout_id: str | None
    deleted: bool
    note: str | None


def build_probe_payload(category: str, exercise_name: str) -> dict:
    """构造 1 步 × 1 次的最小力量训练 payload（纯函数，可单测）。
    复用 garmin_workout_mapper 的常量；workoutName 必须以 "PROBE｜" 开头且含"请删除"。"""


def probe_one(
    adapter: Any,
    category: str,
    exercise_name: str,
    *,
    keep: bool = False,
) -> ProbeResult:
    """创建 → 回读 → （默认）删除。

    判定规则：
    - 回读的 category 与请求一致 且 exerciseName 与请求一致 → status="verified"
    - 回读的 category 一致但 exerciseName 被改（如变空串） → status="normalized"，
      note 记录 "exerciseName: {请求值} → {观测值}"
    - 回读 category 不一致 → status="failed"
    - 创建或回读抛异常 → status="failed"，note 记录异常类型名（**不含远端原始响应**）
    - 删除失败 → deleted=False，note 追加 "删除失败（{异常类型}），请手动删除 {workout_id}"
    """


def probe_batch(
    adapter: Any,
    pairs: list[tuple[str, str]],
    *,
    keep: bool = False,
    max_items: int = PROBE_MAX_ITEMS,
) -> dict:
    """批量探测。返回 {"requested","processed","verified","normalized",
    "failed","results":[ProbeResult 的 dict...]}。
    - pairs 去重（保序）
    - 超过 max_items 只处理前 max_items 个（不做截断报错）
    - 每个组合之间**不额外 sleep**——适配器已有 0.5s 全局节流
    """


def apply_probe_results(session: Session, results: list[ProbeResult]) -> dict:
    """把探测结果写回 exercise_mapping。返回 {"updated": n, "skipped": m}。

    对每个 result（按 xunji_name 无法定位，因为 result 只有 category/exercise）：
    - 找出 `garmin_category == result.category AND garmin_exercise_name == result.exercise_name`
      的 mapping 行（可能 0 条或多条）
    - `status="verified"` → 设 `verified_level="created"`、`verified_at=utcnow()`
    - `status="normalized"` → 设 `verified_level="created"`、`verified_at=utcnow()`、
      并把 `garmin_exercise_name` 更新为观测值（空串也照写），
      `note = f"L2 探针：{result.note}"`
    - `status="failed"` → **不改 verified_level**，只追加 note
    - 0 条匹配 → 计入 skipped
    - **不改 status（draft/active 保持原样）、不改 mapping_version**
    """
```

#### 严格约束

- **绝不调用 `schedule_workout` / `reschedule_schedule`**（不创建任何日程）
- **绝不调用 `create_workout` 以外的写接口**，除 `delete_workout`
- 删除逻辑：
  ```python
  if not keep and workout_id:
      try:
          adapter.delete_workout(workout_id)
          deleted = True
      except Exception as exc:
          deleted = False
          note += f"；删除失败（{type(exc).__name__}），请手动删除 {workout_id}"
  ```
- 异常信息只写**异常类型名**，不拼接远端原始响应（防泄漏）
- `pairs` 为空 → 立刻返回全 0 统计，不调用任何适配器方法

### 3. `api/exercise_mappings.py` 追加端点

**注册顺序**：放在 `/{mapping_id}` 之前。

```python
class ProbeRequest(BaseModel):
    pairs: list[dict] = []          # [{"category": str, "exercise_name": str}]
    keep: bool = False
    apply: bool = True              # 是否把结果写回映射表

@router.post("/probe")
def post_probe(body: ProbeRequest, session: Session = Depends(get_session)) -> dict:
    """L2 探针：真实创建并删除 Garmin Workout，验证目录组合是否被原样接受。
    **会写 Garmin**，仅在 GARMIN_PLAN_SYNC_ENABLED=1 时允许。"""
```

行为：
1. `settings = get_settings()`；若 `not settings.garmin_plan_sync_enabled` →
   抛 `HTTPException(409, detail={"code": "GARMIN_WRITE_DISABLED", "message": "..."})`
2. `pairs` 为空 → 422，`detail={"code": "EMPTY_PAIRS"}`
3. 构造 `GarminWorkoutAdapter.from_settings(settings)`（**延迟导入**，放在函数内，
   避免模块导入期就要求 garminconnect 依赖）
4. `result = probe_batch(adapter, pairs, keep=body.keep)`
5. 若 `body.apply` → `apply_probe_results(session, ...)`，把统计并入响应
6. 响应 = `probe_batch` 的 dict + `"applied": {...}`

> `ProbeRequest` 用 pydantic `BaseModel`。**先读该文件现有 import 风格**，
> 若文件里没用过 pydantic，就在文件内新增 import（`from pydantic import BaseModel`）。

### 后端 API（V6-4 已实现，**契约不可改**）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/exercise-mappings/coverage` | 看板统计 |
| GET | `/api/exercise-mappings?status=&confidence=&verified_level=&keyword=&page=&page_size=` | 列表 |
| GET | `/api/exercise-mappings/catalog?q=&category=&limit=` | Garmin 目录搜索 |
| GET | `/api/exercise-mappings/stale-syncs?limit=` | 已同步但映射已变 |
| GET | `/api/exercise-mappings/{id}` | 详情（含 candidates） |
| PATCH | `/api/exercise-mappings/{id}` | 部分更新 |
| POST | `/api/exercise-mappings/{id}/activate` | 采纳 |
| POST | `/api/exercise-mappings/{id}/disable` | 停用 |
| POST | `/api/exercise-mappings/{id}/candidates/{cid}/accept` | 采纳指定候选 |
| POST | `/api/exercise-mappings/batch-activate` | 批量采纳 |
| POST | `/api/exercise-mappings/generate?refresh_drafts=` | 触发批处理 |

**列表响应**：
```json
{"items": [{"id","xunji_name","garmin_category","garmin_exercise_name",
            "garmin_display_name","weight_strategy","status","confidence",
            "source","verified_level","mapping_version","not_applicable_reason",
            "note","candidate_count"}],
 "total": 1091, "page": 1, "page_size": 50, "pages": 22}
```

**看板响应**：
```json
{"total":1091,
 "by_status":{"draft":911,"active":16,"disabled":0,"not_applicable":164,"missing":0},
 "by_confidence":{"high":222,"medium":264,"low":206,"none":235,"not_applicable":164},
 "by_verified_level":{"none":1075,"catalog":0,"created":0,"displayed":16},
 "coverage":{"with_candidate":708,"with_candidate_pct":64.9,"high":222,"high_pct":20.3,
             "strength_total":927,"strength_with_candidate":708,
             "strength_with_candidate_pct":76.4}}
```

**详情响应**：列表 item 全字段 + `candidates: [{id,xunji_name,garmin_category,
garmin_exercise_name,garmin_display_name,confidence,reason,rank,status}]`

**更新/PATCH body**（字段皆可选，只传要改的）：
`{garmin_category?, garmin_exercise_name?, garmin_display_name?, weight_strategy?, status?, reason?}`

**校验错误**：422 且 `detail = {"code": "INVALID_CATEGORY"|"INVALID_EXERCISE"|"INVALID_WEIGHT_STRATEGY"|"MISSING_CATEGORY", "message": "..."}`。
记录不存在：404 且 `detail = {"code": "MAPPING_NOT_FOUND"}`。

**目录搜索响应**：`[{"category","exercise","name"}]`

**stale-syncs 响应**：`[{"sync_id","plan_ref","training_date","workout_id",
"workout_schedule_id","stored_hash","current_hash"}]`

## 开发内容

### 1. `ExerciseMappingsPage.jsx`

单文件实现，结构清晰，**不拆新组件文件**（预算限制）。页面分 4 个区块：

#### A. 顶部覆盖率看板

- 调 `GET /api/exercise-mappings/coverage`
- 展示 3 组数字卡片：
  - **总动作** `total`、**已映射** `coverage.with_candidate`（`with_candidate_pct`%）
  - **可信候选** `coverage.high`（`high_pct`%）
  - **力量类覆盖** `strength_with_candidate` / `strength_total`
    （`strength_with_candidate_pct`%）
- 状态分布用小徽标：`draft` / `active` / `not_applicable` / `missing` 各多少
- `data-testid="coverage-panel"`，各数字带独立 testid：
  `coverage-total` / `coverage-with-candidate` / `coverage-high` / `coverage-strength`

#### B. 筛选 + 列表

- 筛选控件（`PillGroup` 或原生 `<select>` 均可）：
  - 状态：全部 / draft / active / disabled / not_applicable
  - 置信度：全部 / high / medium / low
  - 关键词输入框（搜索训记名与 Garmin 英文名）
- 列表每行展示：`xunji_name`、`garmin_category / garmin_exercise_name`、
  `garmin_display_name`、状态徽标、置信度徽标、`weight_strategy` 中文标签
  （`total`→总重 / `per_hand`→单只 / `bodyweight`→自重 / `assisted`→辅助）、
  `candidate_count`（有候选时显示「N 个候选」）
- 每行操作按钮：**编辑**、**采纳**（仅 draft 且 category 非空时显示）、
  **停用**（仅 active 时显示）
- 分页：上一页 / 下一页 + 「第 X / Y 页」
- 空态用 `EmptyState`
- `data-testid="mapping-list"`，行 testid `mapping-row-{id}`，
  操作按钮 `mapping-edit-{id}` / `mapping-activate-{id}` / `mapping-disable-{id}`

#### C. 编辑弹层（用 `ConfirmDialog` 不合适，改用页面内联面板或复用 `BottomSheet`）

> **注意**：`ConfirmDialog` 只支持 title/description/确认取消，不足以承载编辑表单。
> 若 `src/components/ui/` 里没有 `BottomSheet`，**就用页面内联面板**（受控 `editingId`
> 状态 + 一个带 `role="dialog"` 的固定定位浮层），不要新增组件文件。

编辑面板字段：
- 训记名（只读展示）
- Garmin category：`<select>`，选项来自 `GET /api/exercise-mappings/catalog?q=&category=`
  返回结果里的去重 category 集合；或直接用一次 `?limit=100` 拉全量后去重
- Garmin 动作：搜索框 + 结果列表（点选即填入 `garmin_exercise_name` 与
  `garmin_display_name`），允许清空为空串（表示「Garmin 只显示 category 名」）
- 重量语义：`<select>`（总重/单只/自重/辅助）
- 修改原因：文本框（可选，提交时作为 `reason`）
- 按钮：取消 / 保存
- 422 错误时把 `detail.message` 显示在表单内，`data-testid="edit-error"`

`data-testid`：`edit-panel` / `edit-category` / `edit-exercise-search` /
`edit-exercise-result-{index}` / `edit-weight-strategy` / `edit-reason` /
`edit-save` / `edit-cancel`

#### D. 批量操作 + stale 提示

- 顶部「批量采纳 high 置信」按钮 → `POST /batch-activate`，
  成功后刷新看板与列表，用 `Toast` 提示「已采纳 N 条」
- 若 `GET /stale-syncs` 返回非空，在页面顶部显示告警条：
  「有 N 条已同步训练使用的映射已更新，可能需要重新同步」+ 折叠列表
  （显示 `plan_ref` / `training_date` / `workout_id`）
- `data-testid="batch-activate"` / `stale-alert"` / `stale-list"`

#### 交互细节（必须实现）

- 所有会改数据的按钮在请求期间 `disabled`，防重复提交
- 请求失败：列表/看板用 `ErrorState`；操作失败用 `Toast` 或行内错误提示
- 采纳/停用/批量采纳成功后**同时刷新看板与当前页列表**
- 关键词输入做 300ms 防抖（或用「搜索」按钮触发，二选一，在报告里说明选择）

## 背景（均已实读核实，可直接采信）

本仓库为健身数据应用，FastAPI + SQLAlchemy 后端在 `backend/`。问题（PRD-V4 F1）：
`backend/app/services/ai.py` 的 `generate_session_review`（约 382-417 行）组装点评上下文时，
只按 movements_json 里的动作名循环调 `query_movement_history`（约 396-402 行）。
garmin_only 活动（如羽毛球/跑步，无训记动作）movements 为空 → 「近4周同动作历史」恒为"无数据"，
AI 只能回答"最近没有该训练记录"。

已核实的关键事实：

- `Workout.tags` 字段（`backend/app/models.py:124`，String(200)）由 `backend/app/services/fuse.py:47`
  写入 `garmin.activity_type`；而 `activity_type` 来自佳明 `activityType.typeKey`
  （`backend/app/adapters/garmin_adapter.py:242`），取值形如 `"badminton"`、`"running"`、
  `"strength_training"` 等小写蛇形 typeKey。
- `Workout` 另有 `duration_s` / `calories` / `avg_hr` / `max_hr` / `deleted_at` 字段。
- `build_session_review_prompt(workout: dict, history: dict, recovery: dict)`（ai.py 约 250 行）
  是纯函数，返回 `[system, user]` 两条消息；workout dict 含 `tags` 键，
  当前在约 264-266 行原样渲染 `活动类型：{tags}`（英文 typeKey 直接露出）。
- 现有「同动作历史」段落在约 301-320 行，标题格式 `# 近4周同动作历史（截至 <date>）`。
- `query_movement_history` 的时间窗口口径：`start = current_date - timedelta(weeks=4)`，
  `end = current_date - timedelta(days=1)`（不含当天），并过滤 `deleted_at.is_(None)`。
  新函数必须沿用同一口径。
- 测试文件 `backend/tests/test_ai.py` 已有 `TestBuildPrompt` / `TestQueryMovementHistory` /
  `TestGenerateSessionReview` 等类，夹具风格见 `_workout_dict()` / `_history_dict()`；
  DB 测试用 `session` fixture，可用 `Workout(...)` 直接建行（参考现有测试写法）。

## 开发内容

### 1. 活动类型中文映射（放 ai.py 模块级）

新增 `ACTIVITY_TYPE_ZH: dict[str, str]` 映射表（typeKey → 中文显示名），至少覆盖：
`badminton→羽毛球`、`running→跑步`、`treadmill_running→跑步机跑步`、`cycling→骑行`、
`indoor_cycling→室内骑行`、`lap_swimming→泳池游泳`、`swimming→游泳`、`walking→步行`、
`hiking→徒步`、`strength_training→力量训练`、`elliptical→椭圆机`、`indoor_rowing→划船机`、
`yoga→瑜伽`、`basketball→篮球`、`soccer→足球`、`tennis→网球`、`table_tennis→乒乓球`、
`jump_rope→跳绳`。
配套小函数 `activity_type_zh(type_key: str | None) -> str`：命中返回中文；未命中的非空
typeKey 原样返回；None/空串返回 `"未知类型"`。

### 2. 新增 `query_activity_history`

在 ai.py 中新增（放在 `query_movement_history` 之后）：

```python
def query_activity_history(
    session: Session,
    activity_type: str,
    current_date: date,
    *,
    weeks: int = 4,
    limit: int = 3,
) -> dict:
```

- 按 `Workout.tags == activity_type` 精确匹配查近 N 周（窗口口径与
  `query_movement_history` 完全一致：含 start 日、止于 current_date-1），
  过滤 `deleted_at.is_(None)`，按日期倒序。
- 返回结构（键名固定，供 prompt 与测试断言）：

```python
{
    "count": int,                    # 窗口内同类活动次数
    "avg_duration_s": int | None,    # 全部命中活动 duration_s 的均值（无有效时长为 None）
    "avg_hr": int | None,            # 全部命中活动 avg_hr 的均值（无有效心率为 None）
    "recent": [                      # 最近 limit 次明细，日期倒序
        {"date": "YYYY-MM-DD", "duration_s": int|None, "avg_hr": int|None,
         "max_hr": int|None, "calories": int|None},
        ...
    ],
}
```

### 3. `build_session_review_prompt` 改造（保持纯函数、保持既有契约）

- 签名扩展为 `build_session_review_prompt(workout, history, recovery, activity_history=None)`，
  新参数放最后并给默认值 `None`，**不得破坏现有三参数调用**。
- `活动类型：{tags}` 一行改为渲染中文映射：`activity_type_zh(tags)`（如 `活动类型：羽毛球`）。
- 当 workout 无 movements（空列表）且传入了 `activity_history` 时：
  - 「近4周同动作历史」段落**整段替换**为同类活动历史段落，标题格式：
    `# 近4周同类活动（{中文名}）历史（截至 <date>）`，其中中文名取 `activity_type_zh(workout["tags"])`；
  - 段落内容（count/汇总/明细均按实际数据，缺字段的行省略）：
    - `- 出现次数：{count}`
    - `- 平均时长：{用现有 _format_duration} | 平均心率：{avg_hr} bpm`（两者都有才输出该行）
    - `- 最近记录：` + 每条 `  - {date}：时长 {_format_duration(duration_s)}，平均心率 {avg_hr} bpm，最大心率 {max_hr} bpm，热量 {calories} 千卡`（单项为 None 的片段省略）
    - count == 0 时只输出 `- 近4周无同类活动记录`
- 有 movements 时：prompt 结构与现有输出**逐字节保持一致**（回归红线），
  仅「活动类型」一行允许因中文映射变化。
- system 消息的四节输出契约（完成质量/与历史对比/恢复评估/注意事项 + session_review_v1 JSON 块）
  保持不变。

### 4. `generate_session_review` 接线

约 396-402 行的历史循环之后：当 `movements` 为空且 `workout.tags` 非空时，
调用 `query_activity_history(session, workout.tags, workout.date)` 并把结果传入
`build_session_review_prompt(..., activity_history=...)`；有 movements 时不查询、不传
（保持 None）。garmin_only 且 tags 为空时维持现状（不注入该段）。

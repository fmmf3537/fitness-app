## 需求（PRD-V4 F4，开放问题已确认）

为力量训练 workout 计算**逐组心率**：从佳明 raw_json 提取心率时间序列与自动识别组次窗口，
与训记动作组次按全局顺序对齐，输出每组的组中心率均值/峰值/谷值 + **组后 30 秒恢复心率**
（Q4.1 已确认增强版），带置信度分级，落库新表 `workout_set_hr`，并在训练详情 API 中返回。

## 已核实的关键事实（实读代码 + 真实数据 fixture，可直接采信）

### 佳明 raw_json 结构（`backend/app/adapters/garmin_adapter.py:251`）

raw_json 是 JSON 字符串，解析后形如 `{"summary": ..., "details": ..., "exercise_sets": ...}`。

**心率序列**（`details` 下，真实样例见 `backend/tests/fixtures/real_week/2026-08-04/garmin_activities.json`）：

- `details.metricDescriptors`：`[{"metricsIndex": 0, "key": "sumMovingDuration", ...}, ...]`，
  真实数据用 **`metricsIndex`** 字段（部分旧测试 fixture 用 `index`，两者都要兼容）。
  需要找 `key == "directTimestamp"`（值是 **epoch 毫秒、GMT 时基、float**，如 `1785819172000.0`）
  与 `key == "directHeartRate"`（bpm，float；**可能为 null，必须过滤**）。
- `details.activityDetailMetrics`：`[{"metrics": [...]}, ...]`，每行 metrics 数组与 descriptors
  的索引对齐（真实样例 1759 行，约 2 秒一点）。

**自动识别组次**（`exercise_sets.exerciseSets`，真实样例 48 组）每组字段：

```json
{"exercises": [{"category": "SQUAT", "name": null, "probability": 51.56}, ...],
 "duration": 56.558, "repetitionCount": 5, "weight": null,
 "setType": "ACTIVE", "startTime": "2026-08-04T04:52:52.0",
 "wktStepIndex": null, "messageIndex": 0}
```

- `setType`：`"ACTIVE"` / `"REST"`；**只有 ACTIVE 组参与对齐**。
- `startTime`：**GMT/UTC 时基的 ISO 字符串（无时区后缀）**，与 directTimestamp 同一时基——
  解析后直接转 epoch 毫秒比较，**严禁 +8 小时**。
- `duration`：float **秒**；组窗口 = [startTime, startTime + duration×1000] 毫秒。
- `exercises`：候选类别列表，按 probability 降序取第一个；**可能为空列表**（REST 组常见，
  ACTIVE 组也可能）——为空时跳过类别校验。
- `repetitionCount` 可能为 null。

### 训记 movements_json 结构（Workout.movements_json，以训记为准）

```json
[{"name": "卧推", "exetype": "help", "sets": [
  {"weight": 60, "unit": "kg", "reps": 10, "time": 0, "done": true, "rpe": 8}, ...]}]
```

- **`exetype` 在动作级**（`mv.get("exetype")`，见 `backend/app/services/ai.py:436`），
  取值 `help`=辅助 / `plus_weight`=负重 / 缺失=普通——本切片不消费它，知道即可。
- **组次无独立时间戳**（`time` 是组间休息秒数），因此以佳明 ACTIVE 组次为时间锚、
  训记组次按全局顺序对齐（PRD 明确要求）。
- `done: false` 表示该组未执行——**不参与对齐**；`done` 缺失视为已执行。

## 开发内容

### 1. 模型（models.py 追加）

```python
class WorkoutSetHr(Base):
    """逐组心率（V4-7）：按 workout+动作+组序 幂等重算。"""

    __tablename__ = "workout_set_hr"
    __table_args__ = (
        UniqueConstraint("workout_id", "movement_name", "set_index",
                         name="uq_workout_set_hr_wms"),
    )

    id: Mapped[int] = mapped_column(primary_key=True)
    workout_id: Mapped[int] = mapped_column(ForeignKey("workout.id"))
    movement_name: Mapped[str] = mapped_column(String(100))
    set_index: Mapped[int] = mapped_column(Integer)        # 动作内组序，1-based
    hr_avg: Mapped[int | None] = mapped_column(Integer)
    hr_max: Mapped[int | None] = mapped_column(Integer)
    hr_min: Mapped[int | None] = mapped_column(Integer)
    hr_recovery_30s: Mapped[int | None] = mapped_column(Integer)  # 组后 30s 心率，无则 None
    set_start: Mapped[datetime | None] = mapped_column(DateTime)  # GMT  naive
    set_end: Mapped[datetime | None] = mapped_column(DateTime)
    confidence: Mapped[str] = mapped_column(String(10))    # high / low
    match_method: Mapped[str] = mapped_column(String(30))  # order / order_category_mismatch
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
```

### 3. 服务 `services/set_hr.py`

纯函数与 IO 分离，至少导出：

- `extract_hr_timeline(raw: dict) -> list[tuple[int, int]]`：从解析后的 raw_json 提取
  `[(epoch_ms, hr), ...]`（按时间升序）。metricDescriptors 兼容 `metricsIndex` 与 `index`；
  过滤 timestamp 或 hr 非数值的行。无数据返回 `[]`。
- `extract_active_sets(raw: dict) -> list[dict]`：从 `exercise_sets.exerciseSets` 取
  `setType == "ACTIVE"` 的组，按 startTime 升序，每项返回
  `{"start_ms", "end_ms", "category"（首候选 category 或 None）, "reps"}`。
  startTime 按 GMT naive ISO 解析为 epoch 毫秒（`datetime.fromisoformat` 后
  `.replace(tzinfo=timezone.utc)`，**不加 8 小时**）。无 exercise_sets → `[]`。
- `GARMIN_CATEGORY_MAP`：佳明类别 → 训记动作名映射（用于校验，至少覆盖真实数据出现的类别）：
  DEADLIFT→硬拉、SQUAT→深蹲、BENCH_PRESS→卧推、ROW→划船、PULL_UP→引体向上、
  SHOULDER_PRESS→推举、CURL→弯举、LATERAL_RAISE→侧平举、TRICEPS_EXTENSION→臂屈伸、
  LUNGE→弓步、PUSH_UP→俯卧撑、SIT_UP→仰卧起坐、LEG_PRESS→腿举、CALF_RAISE→提踵、
  HIP_THRUST→臀推、PLANK→平板支撑、CRUNCH→卷腹、DIP→双杠臂屈伸。
  UNKNOWN 或映射表查不到 → 视为无类别信息（跳过校验，**不降置信度**）。
- `align_sets(movements: list, active_sets: list) -> list[dict]`：核心对齐——
  - 训记侧按全局顺序展开：动作按列表序、组按 sets 序，**跳过 `done is False` 的组**，
    得到 `[(movement_name, set_index), ...]`（set_index 为动作内 1-based 序号）。
  - 与佳明 ACTIVE 组按顺序一一配对；两侧数量不等时按较短侧对齐（超出侧丢弃）。
  - 类别校验：佳明组 category 映射中文名后，与配对的 movement_name 比对——
    **映射名是 movement_name 的子串即视为一致**（如 硬拉 ∈ 杠铃硬拉）；
    不一致 → `confidence="low"`, `match_method="order_category_mismatch"`；
    一致或无类别信息 → `confidence="high"`, `match_method="order"`。
- `compute_set_stats(timeline, start_ms, end_ms) -> dict | None`：窗口内 HR 点
  （含端点）的 avg/max/min（round 转 int）；窗口无点 → None（该组心率字段全 None）。
- `compute_recovery_hr(timeline, end_ms) -> int | None`：在 `[end_ms+25000, end_ms+35000]`
  窗口内取**时间最接近 end_ms+30000** 的点；窗口内无点 → None。
- `compute_workout_set_hr(session, workout) -> list[WorkoutSetHr]`：编排函数——
  解析 workout 的 garmin raw_json（无 garmin 关联/无 movements_json/无 exercise_sets/
  无心率序列 → 返回 `[]`），完成提取/对齐/统计，**幂等落库**：先删该 workout_id 全部
  既有行再插入新行，commit，返回新行列表。
- `get_or_compute_set_hr(session, workout) -> list[WorkoutSetHr]`：懒计算入口——
  已有行直接按 (movement_name, set_index) 序返回；无行则调 compute_workout_set_hr。

### 5. 测试

**`tests/test_set_hr.py`**（服务层，全部离线纯数据 + conftest helper）：

1. `extract_hr_timeline`：metricsIndex 与 index 两种 descriptor 写法都能提取；hr 为 null
   的行被过滤；空 details 返回 []。
2. `extract_active_sets`：混合 ACTIVE/REST 的 exerciseSets，只取 ACTIVE 且按时间排序；
   startTime→epoch ms 换算正确（用已知时间戳断言，如 "2026-08-04T04:52:52.0" →
   1785819172000）；exercise_sets 为 None → []。
3. `align_sets` 顺序对齐：2 动作（如 硬拉 2 组 + 卧推 2 组）对 4 个 ACTIVE 组，类别一致时
   全部 high/order。
4. `align_sets` 类别冲突降级：佳明首候选 BENCH_PRESS 对齐到训记"硬拉"→ 该组
   low/order_category_mismatch；exercises 空列表 → 保持 high。
5. `align_sets` 跳过未执行组：训记第 2 组 done=False，佳明 2 个 ACTIVE 组应对齐到
   第 1、3 组。
6. `compute_set_stats` / `compute_recovery_hr`：构造稀疏 timeline，断言 avg/max/min/
   恢复心率与容差窗口行为（±5s 外取不到 → None）。
7. `compute_workout_set_hr` 端到端幂等：用 make_xunji_train + make_garmin_activity +
   fuse_workout 落库，raw_json 内含小型 details+exercise_sets；连调两次，行数不变且
   数值一致；佳明无 exercise_sets 的 workout → 返回 [] 且不建行。

## 需求背景（方案见 `docs/EXERCISE-MAPPING-PLAN.md` §7.2、§7.3）

V6-6a 已让预览与同步接入 DB 映射，并在预览 200 响应里加了 `pending_review`。

### 后端契约（V6-6a / V6-4 已实现）

**预览 200 响应**新增字段：
```json
"pending_review": [{"xunji_name": "...", "suggested_category": "...", "suggested_exercise": "..."}]
```
无未复核动作时为 `[]`（键必定存在）。

**预览 422**（有动作无法映射时）：
```json
{"detail": {"code": "PLAN_MAPPING_UNSUPPORTED",
            "issues": [{"code": "MAPPING_NOT_APPROVED" | "UNKNOWN_EXERCISE" | ...,
                        "movement": "...", "message": "..."}]}}
```

**按名字反查 mapping**：`GET /api/exercise-mappings?keyword=<动作名>&page_size=50`
返回 `{items: [...]}`，取 `items.find(i => i.xunji_name === 动作名)`。

**目录搜索**：`GET /api/exercise-mappings/catalog?q=<词>&limit=30`
返回 `[{"category","exercise","name"}]`。

**改映射**：`PATCH /api/exercise-mappings/{id}`，
body `{garmin_category, garmin_exercise_name, garmin_display_name, weight_strategy?, reason?}`，
成功返回更新后的 item；422 时 `detail = {code, message}`。

## 开发内容

### 1. 动作行加「映射不对？」按钮

在每个 `<section data-testid="garmin-preview-movement-{i}">` 的头部右侧
（`support_level` 文案那个 `span` 附近）加一个小按钮：

```jsx
<Button
  variant="ghost"          // 若 Button 无 ghost，用 "secondary"；先读 Button.jsx 确认可用 variant
  onClick={() => openMappingEditor(movement)}
  testId={`garmin-edit-mapping-${movementIndex}`}
>
  映射不对？
</Button>
```

- 文案固定「映射不对？」
- 点击只打开编辑器，**不发请求**

### 2. 就地纠错弹层

用组件内 state 控制（`editingMovement` / `editState`），渲染成**又一个兄弟节点**
（与 V5-9 的 `ConfirmDialog` 并列，注意 z-index 要高于预览弹窗）：

```
{editingMovement && (
  <div className="fixed inset-0 z-[60] ..." role="dialog" aria-modal="true"
       data-testid="garmin-mapping-editor">
    ...
  </div>
)}
```

内容：
1. 标题：`修正「{movement.name}」的映射`
2. 当前映射展示：`{movement.category} / {movement.exerciseName || '（空）'}`
   （`data-testid="edit-current-mapping"`）
3. 搜索框（`data-testid="edit-catalog-search"`）：
   - 初始值 = 从 `movement.garmin_display_name` 里取的主要词（可简单取空格分割的前 2 个词；
     取不到就空）
   - 输入后 300ms 防抖调 `GET /api/exercise-mappings/catalog?q=...&limit=20`
   - 结果列表（`data-testid="edit-catalog-result-{index}"`），每项显示
     `{name}` 与 `<code>{category} / {exercise}</code>`，点击即选中
   - 选中后在顶部显示「已选：{name}」（`data-testid="edit-selected"`）
4. 重量语义 `<select data-testid="edit-weight-strategy">`：
   总重 `total` / 单只 `per_hand` / 自重 `bodyweight` / 辅助 `assisted`，
   默认取 `movement` 上无 weight_strategy → 用 `total`
   （注：预览 preview 的 movement 可能没有该字段，缺省即 `total`）
5. 修改原因 `<input data-testid="edit-reason">`（可选）
6. 按钮：`取消`（`edit-cancel`）/ `保存`（`edit-save`）
7. 错误区 `data-testid="edit-error"`

**打开编辑器时的反查**：
- 先 `GET /api/exercise-mappings?keyword={encodeURIComponent(movement.name)}&page_size=50`
- `items.find(i => i.xunji_name === movement.name)`
- **找不到** → 在编辑器内显示
  「该动作尚无映射记录，请先在动作映射页处理」+ `<Link to="/exercise-mappings">去处理</Link>`，
  并禁用保存按钮
- 找到 → 记住 `id`，保存时 `PATCH /api/exercise-mappings/{id}`

**保存成功**：
- 关闭编辑器
- **重新加载预览**（复用组件内已有的加载逻辑：`setRetryToken(v => v + 1)` 或等价的
  重新 fetch；先读代码确认既有机制）
- 无需额外提示（预览刷新后映射已变，用户直接看到）

**保存失败**：
- 422 时把 `detail.message` 显示在 `edit-error`（不是泛化文案）
- 其它错误显示通用消息
- 按钮恢复可点

### 3. draft 引导

**A. 预览成功但有 `pending_review`**

在已有「Garmin 写入当前未启用」提示（约 L360）附近，加一条琥珀色提示：

```jsx
{preview?.pending_review?.length > 0 && (
  <div data-testid="pending-review-alert" className="...amber...">
    <p>本训练日有 {preview.pending_review.length} 个动作尚未复核映射：</p>
    <ul>
      {preview.pending_review.map(item => (
        <li key={item.xunji_name}>
          {item.xunji_name}（建议 {item.suggested_category} / {item.suggested_exercise || '—'}）
        </li>
      ))}
    </ul>
    <Link to="/exercise-mappings">去复核</Link>
  </div>
)}
```

**B. 预览 422 且 issues 含 `MAPPING_NOT_APPROVED`**

现有 422 处理约在 L110 附近（`error instanceof ApiError && error.status === 422`
→ 取 `error.detail.issues`）。加一条区分：

- 若 `issues` 中存在 `code === 'MAPPING_NOT_APPROVED'`：
  在错误区额外显示 `data-testid="mapping-not-approved-hint"`：
  「有动作的映射尚未复核确认，请先去复核」+ `<Link to="/exercise-mappings">去复核</Link>`
- `UNKNOWN_EXERCISE` 保持既有展示不变

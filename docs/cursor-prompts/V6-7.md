### 1. `services/exercise_mapping_batch.py`

模块 docstring 说明：批量把候选生成结果落库；不访问网络（候选用离线目录）、不调 LLM。

#### 必需 API

```python
def generate_all(
    session: Session,
    *,
    refresh_drafts: bool = False,
) -> dict[str, int]:
    """对全部 1091 个训记动作批量生成映射并落库。幂等。

    返回统计字典，至少包含这些键：
        total          处理过的动作总数（== 1091）
        inserted       新建的 exercise_mapping 行数
        refreshed      被重算的 draft 行数（仅 refresh_drafts=True）
        skipped_active 因已是 active/disabled 而跳过的行数
        not_applicable 标为 not_applicable 的行数
        with_candidate 至少写入 1 个候选的动作数
        no_candidate   无任何候选的动作数
        candidates     写入 exercise_mapping_candidate 的行数
    """


def coverage_stats(session: Session) -> dict:
    """覆盖率看板数据（只读）。返回结构见下方「API 响应形状」。"""
```

#### 行为规格（**严格按此实现**）

**A. 读取动作名单**：从 `app/data/xunji_movements.json` 读取（用
`Path(__file__).resolve().parents[1] / "data" / "xunji_movements.json"`，
参照 `app/movements.py` 的既有写法，不要硬编码绝对路径）。

**B. 与既有行合并的策略**（幂等的核心）：

| 既有行状态 | 行为 |
|---|---|
| 不存在 | 新建（`source='auto'`、`status='draft'`、`verified_level='none'`、`mapping_version=1`） |
| `active` | **跳过**，绝不覆盖（`skipped_active += 1`） |
| `disabled` | **跳过**，绝不覆盖（`skipped_active += 1`） |
| `not_applicable` | `refresh_drafts=True` 时重算；否则跳过 |
| `draft` | `refresh_drafts=True` 时重算（覆盖 `garmin_category` 等派生字段）；否则跳过 |

> `refresh_drafts=False`（默认）时，第二次调用 `generate_all` 必须
> `inserted == 0`、`refreshed == 0`，即**完全幂等**。

**C. 按适用性分流**：

- `classify_applicability(name)` 返回 `(False, reason)` →
  `status='not_applicable'`、`not_applicable_reason=reason`、
  `garmin_category=None`、`garmin_exercise_name=None`、`garmin_display_name=None`、
  `confidence=None`、`note='非力量动作，不参与 Garmin 力量训练写入'`
- 否则调用 `generate_candidates(name, limit=3)`：
  - 有候选 → rank-1 写入 `garmin_category` / `garmin_exercise_name` /
    `garmin_display_name` / `confidence`；`weight_strategy` 按器械推断
    （**复用规则**：动作名含「哑铃」→ `per_hand`；含「卷腹/转体/平板/支撑」→ `bodyweight`；
    其余 → `total`）
  - 无候选 → `status='draft'` 但 `garmin_category=None`、
    `confidence=None`、`note='无自动候选，需人工指定或 LLM 兜底'`

**D. 候选表写入**：

- 对每个动作写入全部候选（rank-1..3）到 `exercise_mapping_candidate`，
  `status='pending'`、`confidence` / `reason` 取自 `Candidate`
- **幂等**：写入前先删除该 `xunji_name` 下 `status='pending'` 的旧候选
  （只删 pending，绝不删 `accepted`/`rejected`——那代表用户已做的决定）
- `not_applicable` 的动作**不写候选**

**E. 事务与性能**：

- 全流程用**一次** `session.commit()` 提交（不要每行提交）
- 1091 动作 × 最多 3 候选 ≈ 3300 行，用 `session.add_all` 或 `bulk_save_objects`，
  不要逐行 `session.flush()`
- 完成后 `session.commit()` 并返回统计

**F. 禁止事项**：

- 不改 `mapping_version`（保持既有值或新建为 1）
- 不写 `ExerciseMappingAudit`（审计留给 V6-4 的编辑流程）
- 不调用任何网络/LLM

#### API 响应形状（前端 V6-5 会依赖，**必须严格一致**）

`GET /api/exercise-mappings/coverage`：

```json
{
  "total": 1091,
  "by_status": {
    "draft": 707, "active": 16, "disabled": 0,
    "not_applicable": 164, "missing": 204
  },
  "by_confidence": {
    "high": 230, "medium": 267, "low": 210, "none": 220, "not_applicable": 164
  },
  "by_verified_level": {
    "none": 911, "catalog": 0, "created": 0, "displayed": 16
  },
  "coverage": {
    "with_candidate": 707,
    "with_candidate_pct": 64.8,
    "high": 230,
    "high_pct": 21.1,
    "strength_total": 927,
    "strength_with_candidate": 707,
    "strength_with_candidate_pct": 76.3
  }
}
```

**字段语义与计算规则**：

- `total` = `xunji_movements.json` 的动作总数（**不是** DB 行数）
- `by_status.missing` = `total - DB 行数`（尚未批处理过的动作数）
- `by_confidence.none` = DB 中 `confidence IS NULL` 且 `status != 'not_applicable'` 的行数
- `coverage.with_candidate` = DB 中 `garmin_category IS NOT NULL` 的行数
- `coverage.strength_total` = 用 `classify_applicability` 现算的「适用力量动作」数
- 所有百分比保留 **1 位小数**；分母为 0 时返回 `0.0`（**不要抛 ZeroDivisionError**）
- 若 DB 为空（未跑批处理），`by_status` 各键仍必须存在（值为 0），`missing == total`

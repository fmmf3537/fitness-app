## 需求背景

V6-7 的 `generate_all(session, refresh_drafts=False)` 在 `refresh_drafts=True` 时
**无条件重算所有 draft 行**，不看来源、不看是否被人工改过。

后果（审核方已确认）：

1. 用户在 V6-5 管理页手工修正了一条映射 → `mapping_version` 变成 2 →
   下次 `refresh_drafts=True` 被算法结果覆盖，**手改白做**。
2. V6-3 的 LLM 兜底为某动作补了候选 → 该行仍是 `draft` →
   `refresh_drafts=True` 把 LLM 结果冲掉，退回到「无候选」。

这会让「手工修正 → 重跑批处理」这条主流程自相矛盾，必须先修。

## 已核实的关键事实（实读代码，可直接采信）

### `services/exercise_mapping_batch.py` 的现有分支

```python
for name in names:
    row = existing.get(name)
    if row is None:
        ...新建...
        continue

    if row.status in _SKIP_STATUSES:          # active / disabled
        stats["skipped_active"] += 1
        continue

    if row.status in _REFRESHABLE_STATUSES and not refresh_drafts:
        continue

    if row.status in _REFRESHABLE_STATUSES and refresh_drafts:
        ...无条件重算...
```

`_SKIP_STATUSES` / `_REFRESHABLE_STATUSES` 是模块级常量（先读文件确认取值，
预期是 `{"active","disabled"}` 与 `{"draft","not_applicable"}`）。

### 手改的可靠信号

`services/exercise_mapping.py` 的 `update_mapping` / `activate_mapping` /
`disable_mapping` / `accept_candidate` **都会 `mapping_version += 1`**，
且 **不改 `source`**。

因此 **`mapping_version > 1` 是「被人工改过」的可靠信号**。

### LLM 填充目前没有标记来源

`services/exercise_mapping_llm.py` 的 `_replace_pending_candidate` 里填的是：

```python
row.garmin_category = category
row.garmin_exercise_name = exercise_name
row.garmin_display_name = display_name
row.confidence = "low"
```

**没有设置 `source`**，所以 LLM 补的候选无法与算法结果区分。本切片要补上。

### `ExerciseMapping.source` 取值

`seed`（V6-1 的 16 条）/ `auto`（V6-7 批处理）/ `llm`（本切片新增）/ `manual`（预留）。

### API 现状

`api/exercise_mappings.py` 已有：

```python
@router.post("/generate")
def post_generate(refresh_drafts: bool = Query(default=False), session=...):
    return batch_svc.generate_all(session, refresh_drafts=refresh_drafts)
```

## 开发内容

### 1. `exercise_mapping_batch.py`

**a. `generate_all` 新增参数**

```python
def generate_all(
    session: Session,
    *,
    refresh_drafts: bool = False,
    force_refresh: bool = False,
) -> dict[str, int]:
```

新增统计键 **`skipped_protected`**（因受保护而跳过的 draft 行数），
并保持既有键全部存在：`total / inserted / refreshed / skipped_active /
not_applicable / with_candidate / no_candidate / candidates / seeded`。

**b. 新增保护判定（模块级私有函数）**

```python
def _is_protected(row: ExerciseMapping) -> bool:
    """该 draft 行是否应被刷新跳过（人工改过 或 由 LLM 填充）。"""
    return bool(row.mapping_version and row.mapping_version > 1) or row.source == "llm"
```

**c. 分支改造**

在既有「`row.status in _REFRESHABLE_STATUSES and refresh_drafts`」之前插入：

```python
if (
    row.status in _REFRESHABLE_STATUSES
    and refresh_drafts
    and not force_refresh
    and _is_protected(row)
):
    stats["skipped_protected"] += 1
    continue
```

其余分支**一律不动**（尤其是 `_SKIP_STATUSES` 的跳过、`refresh_drafts=False`
时的跳过、新建行的逻辑）。

**d. 不要**在 `refresh_drafts=False` 时统计 `skipped_protected`
（那时所有 draft 都被跳过，加了会让数字含义混乱）。只有「本来要刷新、但被保护」
才计入。

### 2. `exercise_mapping_llm.py`

在 `_replace_pending_candidate`（或等价函数）里，给被填充的 mapping 行补上来源标记：

```python
row.source = "llm"
```

**约束**：
- 只在该行**原本不是 `seed`** 时才设（保护 V6-1 那 16 条的来源语义）——
  seed 行是 `active`，理论上不会被 LLM 触碰，但要加防御
- 不修改 `status`、`verified_level`、`mapping_version`

### 3. `api/exercise_mappings.py`

`post_generate` 新增 query 参数并透传：

```python
@router.post("/generate")
def post_generate(
    refresh_drafts: bool = Query(default=False),
    force_refresh: bool = Query(default=False),
    session: Session = Depends(get_session),
) -> dict:
    """触发全量批处理。

    `refresh_drafts=True` 时重算 draft，但**默认跳过被人工修改
    （mapping_version > 1）或由 LLM 填充（source='llm'）的行**；
    传 `force_refresh=True` 才会连这些一起覆盖。
    """
    return batch_svc.generate_all(
        session, refresh_drafts=refresh_drafts, force_refresh=force_refresh
    )
```

**不要**改 `/coverage`、`/catalog`、`/stale-syncs`、`/probe`、`/llm-suggest`、
`/batch-activate` 的任何行为。

### 4. `tests/test_exercise_mapping_refresh_guard.py`（新，≥12 例）

用既有 `session` fixture 与 batch 模块的 `generate_all`。
为控制耗时，可用 `monkeypatch` 把 `_load_movement_names` 替换成小名单
（参照 `test_exercise_mapping_batch.py` 的既有做法）。

3. `test_refresh_recomputes_untouched_draft` —— 改一条未受保护的 draft 的
   `garmin_exercise_name`（**不改 `mapping_version`**），`refresh_drafts=True` →
   被重算回生成器结果
4. `test_refresh_skips_user_edited_row` —— 改一条 draft 的
   `garmin_exercise_name` 并 `mapping_version = 2`，`refresh_drafts=True` →
   **保持手改值**，且 `skipped_protected >= 1`
5. `test_refresh_skips_llm_row` —— 造一条 `source='llm'`、`status='draft'`、
   `mapping_version=1` 的行，`refresh_drafts=True` → 保持原值，
   `skipped_protected >= 1`
6. `test_force_refresh_overwrites_user_edited_row` —— 同上第 4 例但传
   `force_refresh=True` → 被重算
7. `test_force_refresh_overwrites_llm_row` —— 同上第 5 例但传 `force_refresh=True`
8. `test_skip_active_still_counted_separately` —— `status='active'` 的行仍计入
   `skipped_active`，**不计入** `skipped_protected`
9. `test_no_protected_count_when_refresh_disabled` —— `refresh_drafts=False` 时
   `skipped_protected == 0`
10. `test_stats_keys_all_present` —— 返回字典包含全部 10 个键
11. `test_llm_fill_marks_source_llm` —— 用注入的 fake `chat_fn` 跑

13. `test_llm_fill_does_not_bump_mapping_version` —— 填充后 `mapping_version` 仍为 1
14. `test_api_generate_accepts_force_refresh` —— `client` + `auth_headers`

    → 200，且响应含 `skipped_protected` 键

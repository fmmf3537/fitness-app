## 当前任务：创建用户 CRUD 服务

### 新建文件：`backend/app/services/users.py`

实现一个 `UserService`（或一组模块级函数），封装对用户表的增删改查与审计，遵循项目现有 service 写法（`session = session or SessionLocal()`）。必须包含：

1. `create_user(session, *, username, password, role="user", is_active=True) -> User`
   - 校验 username 非空、password 非空且长度 ≥ 6（否则抛 `ValueError` 并给出明确中文提示）。
   - 检查 username 唯一：若已存在同名抛 `ValueError`（明确提示「用户名已存在」）。
   - 用 `hash_password` 生成 `password_hash`；绝不存储明文。
   - 持久化并返回 `User`。
   - 写入一条 `AuditLog`（actor_user_id=user.id, target_user_id=user.id, action="create_user", target_table="users", target_id=user.id, summary_json=json.dumps({"username":username,"role":role})）。

2. `get_user_by_id(session, user_id) -> User | None`
3. `get_user_by_username(session, username) -> User | None`
4. `list_users(session) -> list[User]`（按 id 升序）
5. `update_user(session, user_id, *, new_password=None, new_role=None, is_active=None, actor_user_id=None) -> User`
   - 仅更新传入的非 None 字段；若传 `new_password` 则重新 `hash_password`。
   - 写 `AuditLog`（action="update_user"）。
6. `deactivate_user(session, user_id, *, actor_user_id=None) -> User`（置 is_active=False，写 AuditLog action="deactivate_user"）
   - **注意**：按项目惯例「软删除/停用」而非物理删除，禁止真删用户行。
7. `verify_user_password(session, username, password) -> User | None`
   - 用 `verify_password` 校验；账号不存在或密码错误返回 None（不抛异常）；账号被停用(is_active=False)返回 None。

所有写操作必须 `session.commit()` 后再返回；异常时 `session.rollback()`。

### 新建文件：`backend/tests/test_users_service.py`

用 pytest 函数级 fixture 建临时 SQLite 库（可复用现有 `tests/conftest.py` 的 `session` fixture；若不可用，用 `SessionLocal` + 临时文件自建）。

测试用例覆盖：
- 创建用户成功、密码被哈希（User.password_hash 不等于明文，且以 `$2` 开头）。
- 创建重复用户名抛 ValueError。
- 创建密码过短（<6）抛 ValueError。
- get_user_by_id / get_user_by_username 命中与未命中（返回 None）。
- update_user 改密码后新密码可校验、旧密码失效。
- deactivate_user 后 is_active=False，且 verify_user_password 返回 None。
- 每步写 AuditLog 已产生对应 action 记录（查询 audit_log 表断言）。

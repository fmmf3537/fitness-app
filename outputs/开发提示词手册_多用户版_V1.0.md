## 通用前缀（每次开工必贴）

```
你正在参与一个健身数据整合分析 APP 的多用户化改造项目。项目技术栈：
- 后端：Python 3.11 + FastAPI + SQLAlchemy + PostgreSQL + APScheduler
- 前端：React 19 + Vite + Tailwind CSS 4 + ECharts
- 测试：pytest（后端）+ Vitest（前端）+ oxlint（前端 lint）
- 部署：Docker Compose + Caddy HTTPS

项目已有完善的单用户版本，现在需要改造为多用户版本（2~10 人小圈子）。

【铁律 - 必须遵守】
1. 只修改任务描述中明确列出的文件，不要动其他文件
2. 所有数据库查询必须显式包含 user_id 过滤（WHERE user_id = :current_user_id）
3. 新增代码必须有对应测试用例，特别是权限测试（用户 A 不能访问用户 B 的数据）
4. 完成后运行 pytest 和 oxlint，确保 0 error、0 warning
5. 密码使用 bcrypt 哈希，cost=12，禁止明文或可逆加密存储
6. 发现 PRD 未覆盖的场景，不要擅自实现，记录下来
7. 合并红线（最高优先级）：
   - M2-5（含全局隔离测试）完成前，禁止部署到生产、禁止合并 main
   - M1-4 存量数据回填未执行前，禁止合并
   - M6-4 HTTPS/加密组网落地前，禁止邀请任何真实用户

【项目结构】

  alembic/             # 数据库迁移

frontend/
  src/
    pages/             # 页面组件

    api/               # API 客户端
```

### 任务 M1-1：创建 users 表 + audit_log 表

```
【当前任务】
在 backend/app/models.py 中新增两个 SQLAlchemy 模型：

1. User 模型：
   - id: Integer, PK, autoincrement
   - username: String(50), unique, not null, index
   - password_hash: String(255), not null
   - role: String(20), not null, default="user"  # "admin" 或 "user"
   - is_active: Boolean, not null, default=True
   - created_at: DateTime, not null, default=func.now()
   - updated_at: DateTime, not null, default=func.now(), onupdate=func.now()

2. AuditLog 模型：
   - id: Integer, PK, autoincrement
   - actor_user_id: Integer, ForeignKey("users.id"), not null
   - target_user_id: Integer, ForeignKey("users.id"), nullable
   - action: String(50), not null  # 如 "create_user", "deactivate_user", "impersonate_view" 等
   - target_table: String(50), nullable  # 被操作的表名
   - target_id: Integer, nullable  # 被操作的记录 ID
   - summary_json: Text, nullable  # JSON 字符串，操作摘要
   - created_at: DateTime, not null, default=func.now()

【要求】
- 仅修改 backend/app/models.py
- 生成 Alembic 迁移脚本：alembic revision --autogenerate -m "add users and audit_log tables"
- 运行 pytest 确保通过
- 运行 alembic upgrade head 在本地 SQLite 验证（后续会切 PG）

【验收标准】
1. models.py 中新增 User 和 AuditLog 类，字段与设计一致
2. 迁移文件生成且可正常执行
3. pytest 通过
```

### 任务 M2-3：登录 API 改造 + auth_token 表

```
【当前任务】
改造登录认证：新增 auth_token 表，登录改为用户名+密码，token 落库持久化。

【修改文件】
backend/app/api/auth.py
backend/app/models.py（新增 AuthToken 模型）
backend/alembic/versions/（新增迁移脚本）

【变更点】
1. 新增 auth_token 表（PRD §4）：
   - id, token VARCHAR(255) UNIQUE, user_id FK REFERENCES users(id),
     created_at, expires_at
   - 生成 Alembic 迁移脚本

2. 登录接口改为接受 username + password：
   POST /api/auth/login
   请求：{"username": "...", "password": "..."}
   响应：{"token": "...", "user_id": 1, "username": "...", "role": "user"}

3. Token 生成和存储（不透明随机 token，禁止 JWT）：
   - 使用 secrets.token_urlsafe(32) 生成
   - 落库 auth_token 表，有效期 7 天（expires_at = now + 7d）
   - 重启不丢会话（内存 dict 存储方案已废弃，禁止实现）
   - 登录时顺手清理过期 token（删除 expires_at < now 的行）

4. require_auth 依赖改造：
   - 从 Authorization header 解析 token
   - 查 auth_token 表，验证 token 存在且未过期
   - 返回 current_user_id（供后续路由使用）

5. Token 失效联动（本任务只实现删除逻辑的服务函数，供 M4-2 调用）：
   - 提供 delete_tokens_for_user(db, user_id) 服务函数
   - 停用用户 / 重置密码时删除该用户全部 token 行（立即失效）

6. 平滑过渡兼容：
   - 如果 users 表为空（首次部署），回退到旧模式：验证 APP_PASSWORD 环境变量
   - 旧模式下 current_user_id = 0（表示系统默认用户）

【要求】
- 本任务破例允许修改 models.py 和新增迁移文件；其他 API 文件不动
- 保留现有 API 路由前缀 /api/auth
- 更新测试 test_api_auth.py
- 运行 pytest 通过

【验收标准】
1. 新登录流程正确，token 落库
2. 重启服务后旧 token 仍可校验（不丢会话）
3. 调用 delete_tokens_for_user 后旧 token 立即 401
4. Token 有效期控制正确，过期 token 被清理
5. 旧模式兼容（users 表为空时）
6. pytest 通过
```

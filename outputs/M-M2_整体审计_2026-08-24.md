> 分支：`multiuser-v2`　汇总日期：2026-08-24

## 1. 目标与范围

把单用户健身数据 APP 改造为多用户系统，核心是**认证**与**数据隔离**：

- 每个用户独立账号（bcrypt 密码哈希 + Bearer token 登录）；
- 业务数据按 `user_id` 隔离，用户 A 不可读写用户 B 的数据；
- 管理员可经 `?user_id=` 显式代查看（不可越权）。

## 3. 隔离架构

```
HTTP 请求
  └─ Bearer token
       └─ get_current_user_id()  ──►  int (current_user_id)   # M2-3
       └─ get_current_user()     ──►  User(含 role)            # M2-5 新增
            └─ resolve_viewer(principal, ?user_id=) ──► effective_user_id
                 └─ API 处理函数：查询/写入均带 effective_user_id
                      └─ service 层：user_id is not None 时 .filter(Model.user_id == user_id)
                                    user_id is None 时不过滤（scheduler/legacy 兼容）
```

- **铁律**：API 入口强制真实 `current_user_id`；`user_id is None` 仅用于系统级/legacy 调用，匹配存量 NULL 行。
- **写路径**：`delete_workout` / `resolve_candidate` 等先校验归属（`row.user_id == user_id`）再操作，越权返回 404。
- **管理覆盖**：仅管理员可经 `?user_id=` 代查看只读列表；普通用户传 `?user_id=` 被忽略。

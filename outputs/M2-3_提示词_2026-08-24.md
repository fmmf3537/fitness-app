## 当前任务：把单用户口令认证改为多用户 token 认证

### 1. 新建模型：`backend/app/models.py` 新增 `AuthToken`
```python
class AuthToken(Base):
    __tablename__ = "auth_token"
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, ForeignKey("users.id", ondelete="CASCADE"), nullable=False, index=True)
    token = Column(String(64), unique=True, index=True, nullable=False)
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False)
    expires_at = Column(DateTime, nullable=False)  # 绝对过期时间
    is_active = Column(Boolean, default=True, nullable=False)
```
- token 用 `secrets.token_urlsafe(32)` 生成（64 字符以内）。
- 过期时间 = created_at + 有效期（建议 7 天 / timedelta(days=7)）；不在 token 里硬编码过期年（用 `datetime.utcnow()`）。
- 在 `User` 与 `AuthToken` 之间按需加 relationship（可不强制，按现有 models 风格）。

### 2. 新增 Alembic 迁移：`backend/alembic/versions/`

### 3. 改造 `backend/app/api/auth.py`
- 保留 `APIRouter(prefix="/api/auth", tags=["auth"])`。
- 新增 Pydantic 模型 `LoginRequest { username: str, password: str }`（替换原仅口令模型）。
- `POST /api/auth/login`：用 `verify_user_password` 校验；成功后在 `AuthToken` 插入一行（user_id, token, expires_at），返回 `{"token": token, "user_id": user.id, "role": user.role}`。校验失败时返回 401（不区分「用户不存在」与「密码错」，统一提示以避免枚举）。
- 新增 `POST /api/auth/logout`：校验 Bearer token 有效后，将该 AuthToken 置 `is_active=False`（软失效），返回 200。
- 新增依赖 `get_current_user_id(authorization: str | None = Header(default=None)) -> int`：
  - 解析 `Bearer <token>`；查询 `AuthToken`（is_active=True 且 expires_at > now）。
  - 命中 → 返回 `user_id`；未命中（缺头/格式错/不存在/过期/失效）→ 401「未登录或会话已过期」。
  - 注意：这是 M2-4 注入到业务 API 的依赖基础，本次只在 auth.py 定义并测试，不在业务路由使用。
- 保留原 `require_auth`（若后续无引用可保留不删，避免影响其他文件）。

### 4. 新建测试：`backend/tests/test_auth.py`

- 覆盖：

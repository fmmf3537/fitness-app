## 1. 任务范围（依据 M2-4 提示词）

M2-4 = **API 层权限注入 + 清理旧认证**：把 14 个业务 API 从旧的「内存会话 `require_auth`」切换为 M2-3 的 `get_current_user_id`（Bearer token 校验），并在每个处理函数注入 `current_user_id`，对全部「用户个人数据」查询/写入按 `current_user_id` 过滤或绑定，杜绝跨用户数据泄漏。

数据隔离边界（来自 M2-4 提示词 §3）：
- **必须过滤**：workout / xunji_train / garmin_activity / garmin_daily / body_metric / xunji_plan / match_candidate / ai_report / report_chat_message / setting 等「用户个人数据」表。
- **不过滤**：LLMCall / JobRun / AuditLog 等系统级运维表（仅在「返回当前用户自身用量」时写入 user_id）。

## 5. 偏差与风险

1. **`user_id=None` 语义（存量兼容）**：service 层在 `user_id is None` 时不过滤（匹配存量 NULL 行），用于 scheduler/legacy 调用；API 层一律传真实 `current_user_id`，故普通用户不可见他人/存量 NULL 数据。该语义已在 `plans._candidate_rows` 等处显式化为 `if user_id is not None:` 才加过滤。
2. **管理员代查看（`?user_id=` 覆盖）未实现**：M2-4 提示词允许管理员经 `?user_id=` 显式指定，但本轮未落地——列为 **M2-5** 范围。
3. **每用户外部凭证（训记/Garmin/LLM Key）**：当前 `XunjiClient`/`GarminClient` 仍走全局配置/环境变量，未做 per-user Key 存储与隔离——属 **M-M3** 阶段（开发计划中 M3-1/M3-2/M3-3，依赖 M2-5 完成）。本轮已完成的 LLM Key 每用户隔离（settings 表 `user_id` 行 + `llm.py` 按 `user_id` 过滤）是 M-M3/M3-3 的先行部分。
4. **`onupdate=func.now()` 干扰时间比较**：`Workout.updated_at` 在 commit 时被刷新为当前时刻，测试模拟「晚于」需足够大的时间差（如 `+1 天`），已在 `test_matcher.py` 落实。

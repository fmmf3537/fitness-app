# M2-5 提示词：数据访问层权限过滤（多用户隔离收口）

> 你正在参与一个健身数据整合分析 APP 的多用户化改造项目（WorkBuddy 协作开发）。
> 前置：M2-3（认证 `get_current_user_id`）、M2-4（API 层权限注入 + 全量 pytest 通过）已完成。
> 通用铁律：改动只允许覆盖 `backend/app/services/*.py`、`backend/app/api/*.py`；新增/修改代码必须有对应测试；完成后 pytest 全绿（`exit 0`）。

## 背景
- M2-4 已在 **API 处理函数**注入 `current_user_id`，并在路由层对大部分查询做了 `Model.user_id == current_user_id` 过滤。
- 但 **service 层**仍有部分查询/写入未显式按 `user_id` 过滤（例如某些 `session.query(Model)` / `select(Model)` 直接在 service 内部执行，API 层已传 `current_user_id` 却未被使用，或 `user_id is None` 时退化为全局可见）。
- 开发计划明确：M2-5 是「**最大改动**」阶段——所有 SQLAlchemy 查询必须追加 `.filter(Model.user_id == current_user_id)`，且**每张表都要有权限测试用例**（用户 A 查询不到用户 B 的数据）。

## 目标
把数据访问的隔离从「API 层」下沉到「service 层」，确保**任何**读取用户个人数据的代码路径都按当前用户过滤；并支持管理员经 `?user_id=` 显式代查看（而非隐式切换）。

## 必须完成的查询过滤（按表核对，逐文件 grep `user_id`）

### 1. 用户个人数据表（必须全部按 user_id 过滤）
- `workout`（services/workouts.py：list/calendar/deleted/detail/删除恢复）
- `xunji_train`（services/matcher.py、sync.py 拉取）
- `garmin_activity`（services/matcher.py、sync.py）
- `garmin_daily`（services/sync.py、stats.py 睡眠趋势）
- `body_metric`（services/body_metrics.py：upsert/query）
- `ai_report`（services/ai.py：session_review / next_advice / weekly / monthly 查询与生成去重）
- `match_candidate`（services/matcher.py、api/match_candidates.py）
- `xunji_plan`（services/plans.py：候选/即将开始）
- `report_chat_message`（services/ai.py / api 聊天）

**核对方法**：对每个 `session.query(<Model>)` / `select(<Model>)` 且 `<Model>` 属于上表，确认存在 `user_id == current_user_id`（或 `user_id == override_user_id` 当管理员覆盖）过滤；若无，补上。

### 2. 管理员代查看（?user_id= 覆盖）
- 在需要管理员视角的端点（如 `/api/stats/*`、`/api/admin/*` 若存在）接受可选 `?user_id=` 查询参数；当调用方为管理员且显式传 `user_id` 时，用该值替代 `current_user_id` 做过滤；未传则维持自身 `current_user_id`。
- 普通用户传 `?user_id=` 应被忽略或 403（不允许越权）。
- 实现位置：在 service 函数新增 `viewer_user_id: int | None = None` 参数；API 层解析 `?user_id=` 后传入，否则传 `current_user_id`。

### 3. 系统级表（不过滤）
- `llm_call` / `job_run` / `audit_log`：不按 user_id 过滤（运维全局数据）。但若接口「返回当前用户自身用量」，写入时需带 `user_id`（LLMCall 已有 user_id 列则写入 `current_user_id`）。

## 不改或谨慎处理
- **不要**为提升隔离而破坏 `user_id is None` 的存量兼容语义：scheduler/legacy 调用传 `None` 时应匹配存量 NULL 行（保持 M2-4 既定行为）。仅在 API 入口强制真实 `current_user_id`。
- **不要**动 `app/api/auth.py` 的 `get_current_user_id` 签名（已稳定）。

## 测试（关键，每张表至少一个权限用例）
复用/扩展 `tests/test_api_isolation.py`：为每个上述表验证
- 用户 A 创建数据 → 用户 B 用自己 token 访问该数据 → **404 或 401**（拿不到 A 的数据）；
- 未带 token → 401；
- 带 token 访问自己数据 → 200 且数据正确；
- 管理员带 `?user_id=A` → 能看到 A 的数据（仅管理员）。
- 重点补：stats 趋势、ai_reports 列表/导出、plans 即将开始、match_candidates、body_metrics 查询——这些在 M2-4 已部分覆盖，M2-5 需下沉到 service 层并补管理员覆盖用例。

## 验证

- 单独：`pytest tests/test_api_isolation.py -q --no-cov`（权限用例全绿）。

2. 每张表有权限测试用例，用户 A 不可见 B 的数据。
3. 管理员 `?user_id=` 覆盖可用且受权限约束。
4. 全量 pytest 通过（exit 0）。

## 二、逐项审查

### 2.1 `User` 模型（账号 / 角色）
```python
class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    username: Mapped[str] = mapped_column(String(50), unique=True, index=True)
    password_hash: Mapped[str] = mapped_column(String(255))   # 仅存 bcrypt 哈希
    role: Mapped[str] = mapped_column(String(20), default="user", server_default="user")
    is_active: Mapped[bool] = mapped_column(Boolean, default=True, server_default="1")
    created_at / updated_at = server_default func.now()  # updated_at 带 onupdate
```
- ✅ 无明文/可逆密码字段，`password_hash` 仅承载哈希（bcrypt 逻辑在后续 auth 服务层）。
- ✅ `role` 默认 `user`，与 PRD「管理员 = 超级用户，普通用户功能不受影响」一致。
- ✅ `username` 唯一索引，避免重名；`updated_at` 带 `onupdate` 自动维护。
- 🟡 非阻塞建议（后续补充）：缺 `email`、`last_login`、`failed_login` 等字段；当前 M1-1 仅做最小地基，可接受。

### 2.2 `AuditLog` 模型（审计日志）
```python
class AuditLog(Base):
    __tablename__ = "audit_log"
    id / created_at
    actor_user_id: Mapped[int] = mapped_column(ForeignKey("users.id"))       # 操作人，必填
    target_user_id: Mapped[int | None] = mapped_column(ForeignKey("users.id"))  # 目标用户，可空
    action: Mapped[str] = mapped_column(String(50))        # create_user / deactivate_user ...
    target_table: Mapped[str | None] = mapped_column(String(50))
    target_id: Mapped[int | None] = mapped_column(Integer)
    summary_json: Mapped[str | None] = mapped_column(Text)
```
- ✅ `actor_user_id` 非空，保证操作可追溯；`target_user_id` 可空，兼容「不针对具体用户」的操作。
- ✅ `action` / `target_table` / `target_id` / `summary_json` 组合可覆盖绝大多数管理类审计场景。
- 🟡 非阻塞建议：生产查询常按 `actor_user_id` / `created_at` 过滤，后续可加索引（当前数据量小，不急）。

### 2.4 `conftest.py` 测试隔离修复（关键）
```python
@pytest.fixture(autouse=True)
def env_vars(monkeypatch, tmp_path):
    from app.config import get_settings
    get_settings.cache_clear()                       # ← 清掉可能已被 .env 缓存的 settings
    monkeypatch.setenv("FERNET_KEY", TEST_FERNET_KEY)
    monkeypatch.setenv("DATABASE_URL", f"sqlite:///{tmp_path}/test.db")
    monkeypatch.setenv("SCHEDULER_ENABLED", "0")
    get_settings.cache_clear()                       # ← 确保测试用临时库不被 .env 覆盖
    yield
    get_settings.cache_clear()
```
- ✅ 根因：`.env` 的 `DATABASE_URL` 经 `load_dotenv(override=True)` 在首次 `import app.config` 时污染 `get_settings()` 的 `lru_cache`，导致测试打到开发库 → `test_settings_insert_query` 偶发 `MultipleResultsFound`。
- ✅ 修复在 setenv 前后均清缓存，彻底隔离测试环境与开发环境，**不改变任何应用运行行为**。
- ✅ 验证：`backend/tests/test_models.py` **18 passed**（详见第三节）。
